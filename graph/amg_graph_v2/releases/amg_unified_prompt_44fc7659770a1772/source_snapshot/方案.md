# 1. 方案目标与总体原则

## 1.1 研究目标

AMG 的目标不是将整张知识图谱直接交给 LLM，也不是用图模型替代
AffectGPT，而是：

-   将原始多模态输入中可检测的情感相关线索表示为结构化 Cue；
-   利用源域数据学习 Cue 与 Appraisal、Emotion 之间的条件预测关系；
-   对当前样本进行证据准入，避免低可信度的检测结果直接进入 Prompt；
-   将样本级图中可靠、紧凑、可追溯的信息转成文本；
-   将该文本作为 AffectGPT
    的辅助上下文，帮助其理解原始视频、音频和文本。

最终目标：

\[ `\text{Original Multimodal Input}`{=tex} +
`\text{AMG Evidence}`{=tex} `\longrightarrow`{=tex}
`\text{AffectGPT}`{=tex} \]

AMG 是辅助证据层，不是最终情绪裁判。

## 1.2 必须坚持的原则

### 原则 A：原始多模态输入优先

AffectGPT 仍然需要直接理解视频、音频和文本。图中 Cue、Appraisal、Emotion
都是模型生成的辅助信息，不能替代原始输入。

### 原则 B：可观察线索不等于心理事实

例如：

-   `VIS_SMILE_PRESENT` 表示检测到微笑线索，不等于人物一定开心；
-   `AUD_SPEECH_RATE_REL_SLOW` 表示语速相对较慢，不等于人物一定悲伤；
-   `TXT_EVALUATION_NEGATIVE` 表示文本存在负向评价，不等于人物一定愤怒。

### 原则 C：关系是条件预测关联，不是因果机制

CA/CE 的正负权重来自关系模型。它们表示模型 logit
的条件贡献方向，不证明心理因果关系。

### 原则 D：全局概念固定，样本实例动态

全局图保存统一概念和冻结关系；样本图只保存当前样本通过证据准入的节点和局部关系。

### 原则 E：证据不足允许不输出

不能为了让图结构完整而强制生成 AppraisalEvidence 或
EmotionEvidence。没有高层证据时，允许只输入 CueEvidence。

### 原则 F：证据准入不应悄悄改变关系模型输入

当前 v2.1 的设计是：阈值控制哪些 Cue 可以被称为正式证据，而不是改变冻结
G1 的输入分布。若要改变 G1 输入，必须作为独立模型实验。

### 原则 G：目标数据集保持 Zero-shot

九个目标数据集不参与 Cue 校准、阈值选择、关系权重调整或 Prompt
参数选择。所有设计参数应在源域开发数据上确定并冻结。

# 3. 总体架构：两层图、一个关系模型、一个 Prompt Adapter

## 3.1 全流程

``` mermaid
flowchart TD
    A["待测样本：Video / Audio / Text"] --> B["三模态 Cue Student"]
    A --> H["AffectGPT 原始多模态编码与融合"]
    B --> C["42 维原始 Cue 分数 + 可用性"]
    C --> D["逐 Cue 校准与双阈值准入"]
    C --> E["冻结 G1：使用所有有效原始 Cue 分数"]
    D --> F["CueEvidence / CandidateCue / CueSignal"]
    E --> G["CA、CE logits 与样本级贡献账本"]
    F --> I["样本级证据支持门控"]
    G --> I
    I --> J["Sample Evidence Graph"]
    J --> K["统一 Relation-aware Prompt Adapter"]
    K --> L["原始任务指令 + AMG 文本证据"]
    H --> M["AffectGPT LLM"]
    L --> M
    M --> N["最终情绪理解与自然语言回答"]
```

这里需要区分两条路径：

-   **图关系路径**：Student → G1 → 样本图 → Prompt；
-   **原始多模态路径**：Video/Audio/Text → AffectGPT
    原有编码器与融合模块。

AMG 不替代 AffectGPT 原有的多模态编码和融合。

## 3.2 全局图与样本级图

### 全局图 Global Graph

全局图是训练/构建阶段形成并冻结的概念关系图，包含：

-   CueType；
-   AppraisalDimension；
-   AppraisalState；
-   EmotionConcept；
-   HAS_STATE；
-   带权 CA；
-   带权 CE。

它回答：**有哪些统一概念，以及源域关系模型学到了哪些稳定的
Cue→Appraisal、Cue→Emotion 关系？**

### 样本级图 Sample Evidence Graph

样本级图根据当前视频的 42 维 Cue 分数动态生成，包含：

-   CueSignal（内部信号审计数据）；
-   CandidateCue（内部候选审计数据）；
-   CueEvidence（正式线索节点）；
-   AppraisalEvidence（正式评价状态节点）；
-   EmotionEvidence（正式情绪候选节点）；
-   INSTANCE_OF、SUPPORTS_APPRAISAL、PREDICTS_EMOTION 等局部边；
-   完整的 CA/CE 贡献账本。

它回答：**当前样本中，哪些 Cue
可以作为正式证据，哪些高层预测获得了足够的可见关系支持？**

样本级图不是重新训练的一张图，也不修改全局图权重。

Dimension 和 State 不能混为一谈：

-   Dimension 表示评价的方面；
-   State 表示该方面当前预测出的状态。

Prompt。不同维度可以分别有状态，也可以 unresolved。

## 4.3 EmotionConcept

当前保留 188 个细粒度 EmotionConcept。

它们是全局情绪概念本体，不代表每个样本都会创建 188 个 EmotionEvidence。

当前 503 条 CE 边实际连接到 74 个不同的 EmotionConcept；另外 114
个概念没有已准入的 CE 入边，仍作为本体概念保留，但不能通过当前正式 CE
关系图获得入边支持。

这意味着：

-   图的 188 个概念不是 AffectGPT 的封闭输出词表；
-   某个概念没有 CE 入边，不代表人物绝不可能表现出该情绪；
-   AffectGPT 仍可根据原始多模态输入生成图本体之外的细粒度情绪词汇。

## 5.3 边权的真实含义

当前 G1 是基于 Cue 连续分数的线性关系预测模型，不是
GNN，也不是通过图消息传递进行多跳传播的网络。

其核心形式为：

\[ Z\_{CA}=QW\_{CA}+b\_{CA} \]

\[ Z\_{CE}=QW\_{CE}+b\_{CE} \]

其中：

-   (Q`\in`{=tex}`\mathbb{R}`{=tex}\^{42})：当前样本的 42 维有效原始 Cue
    分数；
-   (W\_{CA}`\in`{=tex}`\mathbb{R}`{=tex}\^{42`\times16`{=tex}})；
-   (W\_{CE}`\in`{=tex}`\mathbb{R}`{=tex}\^{42`\times188`{=tex}})；
-   (b\_{CA},b\_{CE})：对应分支的偏置；
-   (Z\_{CA},Z\_{CE})：关系模型输出的 logits。

单个 Cue 对某个目标 logit 的样本级贡献为：

\[ C\_{ij}=q_iW\_{ij} \]

因此：

-   (W\_{ij})：全局固定关系权重；
-   (q_i)：当前样本的原始 Cue Student 分数；
-   (C\_{ij})：该 Cue 在当前样本上对目标 logit 的有符号贡献。

正贡献会提高目标 logit；负贡献会降低目标 logit。

**不能将边权或贡献解释为心理因果效应，也不能将其直接解释为情绪概率。**

对于 CA 的多分类状态，系数是某个状态 logit
的贡献；最终状态概率还受到同一维度其他状态 logits 和 Softmax 的影响。

## 5.4 为什么当前没有 AE？

当前 v2.1 的正式 `graph.json` 没有 AE 边，并且 Release 元数据中
`path_branch_enabled=false`。

因此，当前正式结构是：

``` text
                 CueType
                 /    \
               CA      CE
               /        \
              v          v
       AppraisalState  EmotionConcept
```

而不是：

``` text
Cue → Appraisal → Emotion
```

旧版 FrozenGraph 运行时代码保留了 AE/path 的通用处理代码，但当前 v2.1
Release 的路径分支明确关闭，不能把旧代码中存在 AE
处理函数等同于当前正式图启用了 AE。

当前 Appraisal 和 Emotion 是两条由 Cue
驱动的并行预测分支。两条分支的信息只在最终 AffectGPT
的多模态综合阶段共同参与判断，不代表图中存在 Appraisal→Emotion 关系。

# 6. Cue Student：输入、输出与分数含义

## 6.1 Student 的职责

Cue Student 负责从对应模态输入中预测 42 个 Cue：

-   Text Student：15 维；
-   Audio Student：17 维；
-   Visual Student：10 维。

当前绑定的编码器配置包括：

  模态     当前 Student 绑定的编码器
  -------- ---------------------------
  Text     XLM-RoBERTa Base
  Audio    Chinese HuBERT Large
  Visual   CLIP ViT-Large-Patch14

Student 输出的是样本级 Cue 分数，不是事件级时间定位。

例如：

``` text
TXT_EVALUATION_POSITIVE = 0.91
AUD_SPEECH_RATE_REL_SLOW = 0.48
VIS_BROWS_RAISED = 0.31
```

这些数值只表示相应 Cue
检测器对当前样本的输出，不直接代表人物的情绪概率。

## 6.2 不要求证据位置

当前 Cue Student 和 Teacher 监督以样本级 Cue
为主。当前正式样本图不要求：

-   精确文本跨度；
-   音频时间戳；
-   视频帧索引；
-   人脸区域坐标；
-   事件级片段节点。

缺少可靠位置标注时，不应人为补造时间戳或证据位置。自然语言 evidence_note
可以保留为审计元数据，但不能冒充已经核验的位置标注。

## 6.3 三种分数/数值必须区分

  -----------------------------------------------------------------------
  数值                        含义                  当前用途
  --------------------------- --------------------- ---------------------
  `raw_score`                 Student 原始连续输出  G1 输入、样本贡献计算
                              (q_i)                 

  `source_calibrated_score`   源域伪标签校准后的    Candidate/Evidence
                              Cue 分数              准入、Cue 排序

  `contribution`              (q_iW\_{ij})          CA/CE 样本级关系解释
  -----------------------------------------------------------------------

尤其注意：

**G1 的贡献计算使用 raw_score，而不是 source_calibrated_score。**

即使未来 Prompt 同时展示 Cue 校准分数和样本贡献，也不能用 Prompt
中展示的校准分数重新计算贡献。

# 7. Cue 校准与双层准入

## 7.1 逐 Cue 校准

当前每个 Cue 独立进行校准策略选择。最终 42 个 Cue 的校准状态：

  校准方式    Cue 数量
  ---------- ----------
  Platt          31
  Identity       3
  Deferred       8
  **合计**     **42**

Platt 映射的形式为：

\[
p_i=`\sigma`{=tex}`\left`{=tex}(a_i`\cdot`{=tex}`\operatorname{logit}`{=tex}(q_i)+b_i`\right`{=tex})
\]

Identity 情况下：

\[ p_i=q_i \]

Deferred
表示当前数据支持不足或校准质量/方向不满足冻结规则，不应把原始分数冒充已校准分数。

当前校准过程采用 Group OOF
和外层留组评估。它验证的是校准与阈值策略，不等于 Student 模型本身做了
OOF 训练预测。

## 7.2 Candidate Threshold 与 Evidence Threshold

每个 Cue 有自己的 Candidate 阈值和 Evidence 阈值：

\[ t_i^{candidate}`\leq`{=tex}t_i^{evidence} \]

Candidate：

\[ p_i`\geq`{=tex}t_i\^{candidate} \]

Evidence：

\[ p_i`\geq`{=tex}t_i\^{evidence} \]

两个阈值解决不同问题：

-   Candidate：保留潜在候选，供审计和分析；
-   Evidence：达到正式证据准入标准，可以创建 CueEvidence。

状态关系：

  ------------------------------------------------------------------------------
  情况                         状态                正式           进入 Prompt
                                                   CueEvidence    
  ---------------------------- ------------------- -------------- --------------
  低于 Candidate               `below_candidate`   否             否

  达到 Candidate、未达到       `candidate_only`    否             否
  Evidence                                                        

  达到 Evidence 且策略已准入   `evidence_active`   是             可进入，受
                                                                  Top-K 限制

  校准/支持不足                `deferred`          否             否

  模态不可用/分数无效/未请求   对应状态            否             否
  ------------------------------------------------------------------------------

CandidateCue 只存在于内部候选审计层，不是正式证据节点。

## 7.3 当前准入约束

当前配置：

  指标                                         Candidate   Evidence
  -------------------------- --------------------------- ----------
  最低 Precision                                    0.65       0.80
  Group Precision 下置信界                          0.55       0.70
  最少预测样本数                                      30         50
  最少预测来源组数                                    20         30
  Bootstrap 阈值激活率         不作为 Candidate 最终门槛      ≥0.80

此外：

-   Group Bootstrap：1,000 次；
-   Threshold Stability Bootstrap：1,000 次；
-   每次稳定性重采样重新搜索阈值；
-   失败重复保留在激活率分母中；
-   每个 Cue 的区间是边际区间，不代表 42 个 Cue 的同时置信保证。

这些约束是在源域 Teacher
伪标签下选择阈值，不是目标域或人工审计精度保证。

## 7.4 当前准入统计

  统计                        数量
  -------------------------- ------
  Candidate 准入 Cue           33
  Evidence 准入 Cue            26
  Evidence Deferred Cue        16
  Calibration Deferred Cue     8

Candidate 和 Evidence 的统计口径不同：一个 Cue 可以通过 Candidate，但
Evidence 策略仍然 Deferred。

## 7.5 为什么不能统一使用 0.5 阈值

Cue 的校准质量、正负样本支持、预测分布和源域伪标签质量不同，因此阈值是逐
Cue 确定的。

例如，某个 Cue 的 Evidence 阈值可能是 0.118，而另一个 Cue 可能是
0.500。分数 0.49 对前者可能是正式 Evidence，对后者则未必。

因此，不能将"校准分数大于 0.5"作为全局准入规则。

# 8. 样本级图构建：从 42 个分数到 Evidence Graph

## 8.1 Runtime 输入

当前 `SampleGraphV21.build()` 接收：

-   `sample_id`；
-   42 个 Student 原始分数；
-   `availability`；
-   `requested_mask`；
-   `deferred_mask`；
-   `modality_available`；
-   `cue_prediction_success`。

运行时同时区分：

-   模态是否可用；
-   Cue 分数是否有效；
-   Cue 是否被请求；
-   Cue 预测是否成功；
-   Cue 是否达到 Candidate；
-   Cue 是否达到 Evidence。

不能因为某个 Cue 推理失败，就将整个模态都标记为不可用。

## 8.2 四类 Cue 数据

### CueSignal

保存所有 42 个 Cue 的运行时信号和审计状态，包括：

-   原始分数；
-   校准状态；
-   可用性；
-   准入状态；
-   是否参与 G1；
-   是否进入图；
-   是否进入 Prompt。

CueSignal 是内部信号审计数据，不是正式样本图节点。

### CandidateCue

达到 Candidate、未达到 Evidence 的 Cue。

它们只用于内部审计，不进入正式图，不进入 Prompt。

### CueEvidence

只有 `evidence_active` 的 Cue 才创建正式 CueEvidence。

节点通常包含：

-   `instance_id`；
-   `sample_id`；
-   `cue_type_id` / `ontology_id`；
-   `modality`；
-   `raw_score`；
-   `source_calibrated_score`；
-   `activation_status`；
-   Student 与校准 Release 标识。

### AppraisalEvidence / EmotionEvidence

这两个是当前样本的高层证据节点，必须经过原有预测门控和 v2.1
可见关系支持门控。

它们不是仅仅因为 G1 产生一个 Top-1 状态或一个高分候选就自动创建。

## 8.3 最重要的实现细节：阈值不截断 G1 输入

当前 v2.1 的运行逻辑是：

\[ M\_{model}=M\_{available}`\land`{=tex}M\_{valid} \]

\[ q_i\^{model}=

```{=tex}
\begin{cases}
q_i^{raw}, & M_{model,i}=1\\
0, & \text{otherwise}
\end{cases}
```
\]

G1 使用所有有效且可用的原始 Cue 连续分数：

\[ Z\_{CA}=Q\_{model}W\_{CA}+b\_{CA} \]

\[ Z\_{CE}=Q\_{model}W\_{CE}+b\_{CE} \]

Evidence 阈值决定 Cue 是否可以暴露为正式证据节点，但不会把未达到
Evidence 的有效 Cue 原始分数从 G1 输入中置零。

这意味着：

-   一个 Cue 可能没有成为 CueEvidence；
-   但只要它可用且分数有效，它仍然可能影响 G1 的 Appraisal/Emotion
    logits；
-   因此必须保留完整贡献账本，不能把所有模型输出都归因于可见
    CueEvidence。

这是 v2.1 的关键设计。

## 8.4 完整 CA/CE 贡献账本

每个样本都保留：

-   CA：42×16 贡献矩阵；
-   CE：42×188 贡献矩阵；
-   每个目标的 bias；
-   每个目标的 logits；
-   Cue ID 顺序；
-   目标 ID 顺序；
-   全局稳定边 Mask；
-   图暴露 Mask；
-   Prompt 暴露 Mask；
-   每个目标的可见/隐藏贡献比例；
-   每个目标的支持状态。

单个贡献：

\[ C\_{ij}=q_i\^{model}W\_{ij} \]

目标 logit：

\[ z_j=`\sum`{=tex}*i C*{ij}+b_j \]

v2.1 的自动验收验证了贡献矩阵加 bias 可以重建
logits；最大闭合误差约为机器浮点精度量级。

## 8.5 高层关系支持门控

v2.1 需要区分：

-   全部有效 Cue 对目标 logit 的贡献；
-   正式 Evidence Cue 对目标 logit 的可见贡献；
-   被隐藏、Deferred 或未准入 Cue 产生的贡献。

定义：

\[ F\_{abs}= `\frac{\sum_{i\in V}|C_{ij}|}`{=tex}
{`\sum`{=tex}*i\|C*{ij}\|} \]

\[ F\_{pos}= `\frac{\sum_{i\in V}\max(C_{ij},0)}`{=tex}
{`\sum`{=tex}*i`\max`{=tex}(C*{ij},0)} \]

其中 (V) 是正式 CueEvidence 与稳定全局边共同形成的可见关系集合。

当前正式支持要求：

\[ F\_{abs}`\geq0.90`{=tex} \]

\[ F\_{pos}`\geq0.90`{=tex} \]

并且存在实际正向可见贡献。

当前状态判定：

  ----------------------------------------------------------------------------------------
  状态                    条件                                    是否创建正式高层节点
  ----------------------- --------------------------------------- ------------------------
  `evidence_supported`    绝对贡献可见比例 ≥0.90，正贡献可见比例  还需通过原模型输出门控
                          ≥0.90，且存在正贡献                     

  `partially_supported`   绝对贡献可见比例                        否
                          ≥0.50，且存在正贡献，但未满足正式标准   

  `model_only`            可见证据不足                            否
  ----------------------------------------------------------------------------------------

注意：这个比例衡量的是 Cue 贡献项的可见程度，不包含
bias；它不是目标节点的概率，也不是因果解释。

### AppraisalEvidence 的其他门控

Appraisal 状态还需通过冻结模型原有的状态置信度、状态间
margin、normalized entropy、维度监督支持以及正向证据覆盖要求。

v2.1 再增加严格的可见贡献支持要求。只有两层门控都通过，才保留正式
AppraisalEvidence。

### EmotionEvidence 的其他门控

当前路径分支关闭，Emotion 走直接 CE 分支。

EmotionEvidence 除了需要正式 Cue 关系支持，还需要通过：

-   CE 分支校准状态；
-   Emotion 目标阈值；
-   正向直接贡献；
-   原有直接证据覆盖要求；
-   v2.1 可见贡献支持门控。

因此，贡献账本中某个目标的 `evidence_supported` 并不自动等于创建了
EmotionEvidence。目标预测本身仍需通过其他门控。

## 8.6 当前样本级边

当前正式样本图中可能出现：

  -------------------------------------------------------------------------------------------
  样本级边             起点                终点                含义
  -------------------- ------------------- ------------------- ------------------------------
  INSTANCE_OF          CueEvidence         CueType             当前 Cue 实例属于某个全局 Cue

  INSTANCE_OF          AppraisalEvidence   AppraisalState      当前评价实例属于某个全局状态

  INSTANCE_OF          EmotionEvidence     EmotionConcept      当前情绪实例属于某个全局概念

  SUPPORTS_APPRAISAL   CueEvidence         AppraisalEvidence   Cue 对当前评价状态的样本级关系

  PREDICTS_EMOTION     CueEvidence         EmotionEvidence     Cue 对当前情绪候选的样本级关系
  -------------------------------------------------------------------------------------------

样本级 CA/CE 边可以记录：

-   `global_edge_id`；
-   `contribution`；
-   `input_score`；
-   `sign`；
-   `fold_sign_consistency`；
-   `bootstrap_interval`；
-   模型 Release；
-   是否进入 Prompt。

当前 v2.1 没有正式 `APPRAISAL_TO_EMOTION` 样本边，因为 AE 路径没有启用。

## 8.7 Fallback 的准确含义

当前 v2.1 的 fallback 主要在**没有任何正式
CueEvidence**时触发，回退到原始 AffectGPT。

如果当前样本有 CueEvidence，但没有 AppraisalEvidence 或
EmotionEvidence，则走 Cue-only 路由，不必回退原始 AffectGPT。

所以：

-   Cue-only 不等于 fallback；
-   没有 EmotionEvidence 不等于没有情绪；
-   没有 AppraisalEvidence 不等于人物没有认知评价。

# 11. 下一阶段：统一 Relation-aware Evidence Prompt

本节是**建议采用的下一阶段设计**，不是当前 v2.1 已实现功能。

## 11.1 统一原则

不再根据 `discrete_emotion`、`polarity`、`open_vocabulary` 切换 AMG
证据组织方式。

所有任务使用同一个 AMG Evidence Package：

\[ P\_{AMG}= P\_{Cue}+P\_{CA}+P\_{CE} \]

其中：

-   (P\_{Cue})：正式 CueEvidence；
-   (P\_{CA})：正式 AppraisalEvidence 及其 Cue→Appraisal 样本贡献；
-   (P\_{CE})：正式 EmotionEvidence 及其 Cue→Emotion 样本贡献。

用户问题、评测任务本身的原始指令仍然保留。这里取消的是 **AMG Prompt
的任务分支**，不是取消任务本身。

例如，离散情绪任务仍然可以要求输出离散情绪，极性任务仍然可以要求输出正负极性，但
AMG 提供的证据结构完全相同。

## 11.2 固定指令：短而明确

建议固定指令控制在约 80--110 个英文单词，不再使用长篇六段规则。

``` text
You are an expert multimodal affective understanding assistant.

Treat the original video, audio and text as primary evidence.
The AMG evidence is auxiliary and must be verified against
the original input.

Cue scores are source-domain calibrated detector scores,
not emotion probabilities or target-domain guarantees.

CA (Cue→Appraisal) and CE (Cue→Emotion) are signed
conditional predictive associations, not causal relations.
Sample contributions are logit terms, not probabilities.

Treat Appraisal and Emotion nodes as hypotheses.
The two relation branches are parallel; do not assume
Appraisal causes Emotion.

Use unrestricted natural-language emotion vocabulary.
Answer the user's actual question.
```

固定指令需要表达的只有：

1.  原始多模态输入优先；
2.  Cue 分数的含义；
3.  CA/CE 的关系语义；
4.  Appraisal/Emotion 是辅助假设；
5.  不限制开放词汇输出。

## 11.3 Cue 分数应该输入吗？

**建议输入 `source_calibrated_score`，不输入 `raw_score`。**

原因：

-   双阈值准入依据就是校准分数；
-   它比原始 Student 分数更适合向 LLM 表达检测器对 Cue 的源域支持程度；
-   通过 Evidence 准入的 Cue 已经有可用的校准策略；
-   它可以帮助 LLM 区分较强和较弱的线索检测结果。

建议格式：

``` text
Cue scores (source-domain calibrated detector scores):

- [Text] TXT_EVALUATION_POSITIVE
  score=0.92
  description=Explicit positive evaluation.

- [Audio] AUD_INTONATION_FALLING
  score=0.82
  description=Clearly falling acoustic intonation.
```

### 分数表达注意事项

1.  字段名称使用 `source_calibrated_score` 或在 Prompt 中明确写
    `source-domain calibrated detector score`。
2.  建议展示两位小数，避免过度强调数值精度。
3.  不要称其为"人物产生某种情绪的概率"。
4.  不要声称它在九个目标数据集上具有同等概率校准保证。
5.  Candidate-only 和 Deferred Cue 不输入。
6.  不将 Candidate 阈值、Evidence 阈值本身传给 LLM。

**分数是 Cue 检测器的源域校准输出，不是情绪概率。**

## 11.4 CA/CE 应该传什么？

建议默认传递**样本级有符号贡献 C**，而不是同时传入全局边权 W 和贡献 C。

原因：

\[ C\_{ij}=q_i\^{raw}W\_{ij} \]

-   W 是跨样本固定的全局关系参数；
-   C 已经包含当前样本原始 Cue 分数与全局关系权重的共同作用；
-   对当前样本的解释而言，C 比单独的 W 更直接；
-   同时传 W 和 C 会增加 Prompt 长度，也容易让 LLM
    混淆全局关系强度和当前样本贡献。

全局 W 仍然保存在 `graph.json` 和关系模型参数中；Prompt
默认只展示经过筛选的 C。

### CA 格式

``` text
CA: Cue → Appraisal

Appraisal hypothesis:
- Goal Congruence = Incongruent

Signed sample contributions:
- TXT_EVALUATION_NEGATIVE: C=+0.31
  Effect: raises the target-state logit.

- TXT_EVALUATION_POSITIVE: C=-0.12
  Effect: lowers the target-state logit.
```

### CE 格式

``` text
CE: Cue → Emotion

Emotion hypothesis:
- Frustration

Signed sample contributions:
- AUD_VOCAL_INTENSITY_REL_HIGH: C=+0.21
  Effect: raises the target-emotion logit.

- VIS_SMILE_PRESENT: C=-0.08
  Effect: lowers the target-emotion logit.
```

以上数值是格式示意，不是仓库真实样本数据。

### 贡献值的解释限制

-   C 是 logit 贡献，不是概率；
-   C 不等于因果效应；
-   CA 的 C 是目标 Appraisal State 的 logit 项；
-   CE 的 C 是目标 Emotion 的 logit 项；
-   C 使用 raw Cue 分数计算，不使用 Prompt 展示的校准分数；
-   C 的和还需要加上 bias 才能重建对应 logit；
-   只展示部分关系时，不能声称这些数值完整解释了整个目标 logit。

## 11.5 是否传全局边权 W？

默认不传。

建议保留三个实验条件：

  条件     输入
  -------- ------------------------
  W-only   全局边权
  C-only   当前样本贡献
  W+C      全局边权与当前样本贡献

主方案先使用 C-only，避免 Prompt 过长；是否需要 W，应通过消融实验决定。

## 11.6 Appraisal 和 Emotion 的输入方式

建议：

-   只输入正式 `AppraisalEvidence`；
-   只输入正式 `EmotionEvidence`；
-   不输入 `model_only`；
-   不输入 `partially_supported`；
-   不输入 Candidate 或 Deferred；
-   不把 188 个 EmotionConcept 全部列给 LLM；
-   不把 EmotionConcept 作为封闭词表；
-   不默认输入 Appraisal/Emotion
    的概率分数，第一版只传节点假设和经过门控的样本级关系贡献。

高层节点分数仍保存在 JSON 审计账本中，后续可以单独做"是否向 LLM
传高层分数"的消融。

## 11.7 Prompt 级二次支持门控

必须保留当前 v2.1 已有的 Prompt 级支持检查。

原因是：

-   样本图可能有多个正式 CueEvidence；
-   Prompt 只输入 Top-K Cue；
-   Top-K 可能没有覆盖某个 Appraisal/Emotion 的主要贡献来源。

因此，不能只看样本图层面的 `evidence_supported`，还必须根据**实际进入
Prompt 的 Cue 集合**重新计算：

\[ F\_{abs}\^{prompt} \]

\[ F\_{pos}\^{prompt} \]

只有当 Prompt 实际输入的 Cue 对目标节点仍满足：

\[ F\_{abs}\^{prompt}`\geq0.90`{=tex} \]

\[ F\_{pos}\^{prompt}`\geq0.90`{=tex} \]

且存在正向可见贡献时，才将该高层节点及关系贡献输入 LLM。

这样才能避免：

-   图内部认为某个 Emotion 有足够支持；
-   但 Prompt 只传入了少量 Cue；
-   LLM 看不到真正决定该预测的线索；
-   最终却被告知该 Emotion 是可靠图证据。

## 11.8 关系边选择与长度控制

不建议直接把所有 CA/CE 边输入 Prompt。

建议采用以下流程：

1.  从正式 CueEvidence 中按 source-calibrated score 排序，选取当前
    Top-8；
2.  对每个正式 Appraisal/Emotion 目标，重新计算 Prompt
    级绝对贡献和正贡献覆盖率；
3.  只保留稳定全局边、正式 Cue 和正式目标之间的局部关系；
4.  按 (\|C\|) 从大到小排序；
5.  选择足以满足 Prompt 级支持阈值的最小关系集合；
6.  若在预算内无法满足覆盖率要求，则不传该高层目标；
7.  不为凑足数量而补充不稳定边或隐藏 Cue。

建议初始参数：

  内容                           初始限制            状态
  ------------------- ------------------------------ --------------------
  CueEvidence                     Top-8              当前 v2.1 已配置
  AppraisalEvidence    每个维度最多 1 个，最多 6 个  由节点结构决定
  EmotionEvidence                 Top-3              建议初始值，待验证
  每个目标的关系边      选满足覆盖率所需的最小集合   建议
  CandidateCue                      0                保持不输入
  Deferred Cue                      0                保持不输入

如果 Prompt
仍然过长，优先删除贡献较小且不影响覆盖率的关系细节，而不是删除原始多模态输入或取消
Cue 分数。

实际 Token Budget 必须使用 AffectGPT 当前 tokenizer
测量，不应只按字符数估计。

# 13. AffectGPT 中的具体接入位置

## 13.1 原始 AffectGPT 输入机制

AffectGPT 论文将输入表示为：

-   (X_v)：视频；
-   (X_a)：音频；
-   (X_t)：文本；
-   (Q)：用户指令；
-   (R)：模型生成的回答。

原始模型通过视频/音频编码器得到模态特征，并使用 Q-Former 或
Attention-based Pre-fusion 进行多模态融合；文本内容和用户指令被组织成
Prompt 后送入 LLM。

因此，第一阶段最稳妥的 AMG 接入方式是：

\[ Q'=Q`\oplus`{=tex}P\_{AMG}(G_i) \]

其中：

-   (Q)：原始任务指令；
-   (G_i)：当前样本级图；
-   (P\_{AMG})：统一 Prompt Adapter；
-   (Q')：追加 AMG 证据后的文本指令。

AffectGPT 仍然接收原始视频、音频和文本。

## 13.2 不建议第一阶段直接做什么

第一阶段不建议：

-   将 252 个全局节点和 668 条边直接序列化；
-   将完整 JSON 图直接塞进 Prompt；
-   将 42×16 和 42×188 的完整贡献矩阵输入 LLM；
-   修改 AffectGPT 的视觉/音频编码器；
-   修改原有 Pre-fusion；
-   新增 GNN 后再把 GNN embedding 强行接入 LLM。

这些会同时改变太多因素，不利于判断收益来自图结构、Prompt 还是模型架构。

## 13.3 代码接入建议

新建统一的 Prompt Adapter，例如：

``` python
def build_unified_amg_prompt(sample_graph, cue_limit=8):
    # 1. Select formal CueEvidence.
    # 2. Add source-calibrated Cue scores and short definitions.
    # 3. Recompute Prompt-level CA/CE visible support.
    # 4. Serialize formal AppraisalEvidence and EmotionEvidence.
    # 5. Serialize selected signed sample contributions.
    # 6. Enforce token budget.
    # 7. Return one task-independent evidence string.
    pass
```

再将该文本追加到 AffectGPT 原始任务指令：

``` python
amg_text = build_unified_amg_prompt(sample_graph)

final_question = (
    original_question
    + ("\n\n" + amg_text if amg_text else "")
)

response = affectgpt.generate(
    video=video,
    audio=audio,
    text=text,
    question=final_question
)
```

这是建议的接口示意，具体函数名应以当前 AffectGPT 实际推理入口为准。

仓库旧的 `graph/amg_inference/model.py` 曾使用
`prompt_question + "\n" + graph_text` 的方式将图文本追加到多模态
Prompt；可以参考其接入位置，但不能将旧实验代码等同于 v2.1
已完成的下游集成。

## 13.4 任务统一不等于任务指令统一

需要特别说明：

-   AMG 的证据组织方式统一；
-   原始用户问题或评测任务指令仍然可以不同；
-   不能为了统一 AMG Prompt 而删除原始任务要求；
-   不同任务应接收同一套图证据结构，模型仍根据原始问题回答。

# 14. Prompt 消融实验设计

新 Prompt 不应仅凭"信息更多"就被认为一定更好。

建议在相同原始视频、音频、文本、模型权重和生成设置下进行配对实验。

## 14.1 主消融

  实验   AMG 输入                           验证目的
  ------ ---------------------------------- -------------------------
  P0     当前 v2.1 Prompt                   现有实现基线
  P1     Cue ID + 自然语言描述              描述信息是否有帮助
  P2     P1 + source-calibrated Cue score   Cue 分数是否有增量
  P3     P2 + Appraisal/Emotion 节点假设    高层节点是否有增量
  P4     P2 + CA/CE 样本级贡献 C            显式关系贡献是否有增量
  P5     P4 + 全局边权 W                    W 是否在 C 之外提供增量

主方案候选是 P4；P5 作为可选消融，不应预设一定更好。

## 14.2 必须单独比较 Cue 分数

  条件      输入
  --------- ----------------------------------
  Score-A   只传 Cue ID
  Score-B   Cue ID + source-calibrated score
  Score-C   Cue ID + score + 自然语言定义

重点观察：

-   是否改善情绪理解；
-   是否对不同模态的 Cue 产生不同影响；
-   是否出现高分 Cue 对 LLM 的误导；
-   是否在跨数据集分布偏移时更容易过度自信。

## 14.3 关系贡献消融

比较：

-   只传节点；
-   传节点 + C；
-   传节点 + W；
-   传节点 + W + C。

并按样本图类型分组：

-   Cue-only；
-   有正式 AppraisalEvidence；
-   有正式 EmotionEvidence；
-   CA 和 CE 均有正式输出。

这样才能判断关系贡献是否在节点名称之外提供额外信息。

## 14.4 实验控制

所有 Prompt 条件应尽可能保持：

-   相同模型 checkpoint；
-   相同原始多模态输入；
-   相同用户/任务指令；
-   相同生成温度和采样参数；
-   相同最大生成长度；
-   相同样本顺序和配对评估；
-   相同的源域冻结图；
-   不使用目标数据集标签选择 Prompt 参数。

九个目标数据集的最终测试结果只用于报告，不应用于回头调节 Cue Top-K、关系
Top-K 或 Prompt 文案。

## 14.5 需要记录的指标

除原有任务指标外，还应记录：

-   AMG Prompt Token 数；
-   正式 Cue 数；
-   实际进入 Prompt 的 Cue 数；
-   正式 AppraisalEvidence 数；
-   正式 EmotionEvidence 数；
-   CA/CE 关系条数；
-   Prompt 级支持覆盖率；
-   Cue-only 比例；
-   fallback 比例；
-   各模态 Cue 覆盖率；
-   不同证据图类型的性能变化。

# 15. 当前方案的主要风险与处理方式

## 15.1 Student OOF 尚未实现

当前
`Student_oof=false`。这不是本轮继续工程实现的硬性阻塞，但属于需要在方法论中如实说明的限制。

建议：

-   当前先冻结 v2.1 Student 和 G1；
-   不为了 Prompt 修改而同时重训 Student；
-   单独比较 Student in-sample/held-out 预测分布；
-   若论文需要严格样本外关系学习，再设计独立的 Student OOF 版本。

不要把 Calibration OOF 写成 Student OOF。

## 15.2 源域校准不保证目标域概率

当前校准监督来自源域 Teacher 伪标签，而不是独立人工审计。

因此：

-   Cue 分数应标为 source-calibrated；
-   不声称在九个目标域仍然具有同样的概率校准；
-   目标域不做标签驱动的再校准；
-   如出现明显分布偏移，应报告限制或保守回退。

## 15.3 高层节点覆盖率低

当前 1538 个内部样本的平均值：

  指标                 平均数量
  ------------------- ----------
  CueSignal               42
  CueEvidence           7.236
  CandidateCue          3.287
  实际 Prompt Cue       6.644
  AppraisalEvidence     0.232
  EmotionEvidence       0.080

样本类型：

  类型              数量   比例
  ---------------- ------ -------
  Cue-only          1193   77.6%
  有正式高层关系    345    22.4%

这说明新 Prompt 的主要增量不应只依赖
Appraisal/Emotion。大多数样本仍然主要使用 CueEvidence。

## 15.4 隐藏 Cue 仍可能影响 G1

G1 使用全部有效原始 Cue 分数，而 Prompt 只暴露正式 CueEvidence。

v2.1 已通过完整贡献账本和 90% 支持门控降低错误归因风险；新 Prompt
还必须进行 Prompt 级二次覆盖检查。

不能只显示几个 Cue，再把整个 G1 预测说成由这些 Cue 完整解释。

## 15.5 关系边的符号不能被过度解释

正负贡献只表示 logit 的增减方向，不应在 Prompt 中写成：

-   "该 Cue 导致了愤怒"；
-   "该 Cue 抑制了悲伤"；
-   "该 Cue 证明了人物的心理状态"。

推荐使用：

-   "positive logit contribution"；
-   "negative logit contribution"；
-   "model hypothesis"；
-   "auxiliary evidence"。

## 15.6 Prompt 不能替代原始多模态判断

图节点可能有误检、源域偏移或语境不匹配。Prompt 必须允许 AffectGPT：

-   接受图证据；
-   部分接受；
-   拒绝；
-   用更细粒度的自然语言修正；
-   识别多情绪共存；
-   在证据不足时保持不确定。

# 16. 推荐实施顺序

建议按以下顺序推进，避免同时修改图结构、Student、G1 和 AffectGPT。

## 阶段 1：冻结当前 v2.1 图构建

不修改：

-   42 个 Cue 本体；
-   6 个 AppraisalDimension；
-   16 个 AppraisalState；
-   188 个 EmotionConcept；
-   149 CA；
-   503 CE；
-   双层 Cue 准入策略；
-   G1 参数；
-   样本级贡献账本；
-   90% 可见贡献支持门控。

先将当前 Release 作为图构建基线。

## 阶段 2：实现统一 Prompt Adapter

修改 Prompt 序列化，而不是修改图构建：

1.  移除 AMG Prompt 的 task 分支；
2.  移除 `node_only` / `relation_aware` 双模式；
3.  保留原始任务指令；
4.  Cue 输入 ID、短描述、source-calibrated score；
5.  CA/CE 输入正式高层节点和样本贡献 C；
6.  保留 Prompt 级二次支持门控；
7.  对每个目标选择满足覆盖率要求的最小关系集合；
8.  通过 AffectGPT tokenizer 控制 Prompt 长度；
9.  无正式 Cue 时回退原始 AffectGPT；
10. Cue-only 样本仍正常使用统一 Prompt。

## 阶段 3：运行小规模配对测试

先选取：

-   Cue-only 样本；
-   有 AppraisalEvidence 样本；
-   有 EmotionEvidence 样本；
-   多模态冲突样本；
-   高分 Cue 与低分 Cue 并存样本。

检查：

-   Prompt 是否正确；
-   分数语义是否明确；
-   C 是否与贡献账本一致；
-   是否错误暴露隐藏 Cue；
-   是否发生 token 超限；
-   AffectGPT 是否仍接收原始多模态输入。

## 阶段 4：Prompt 消融

先比较 Cue ID、Cue score、自然语言描述、CA/CE 节点、样本贡献 C 的增量。

确认实现没有信息泄漏后，再运行完整的九个目标数据集零样本实验。

## 阶段 5：决定是否升级图构建

只有在 Prompt 实验表明关系信息有增量之后，才考虑：

-   Student OOF；
-   重新拟合关系模型；
-   调整 CA/CE 边准入；
-   研究 AE 路径；
-   研究图向量或结构化 Token 接入。

不建议在统一 Prompt 尚未验证之前同时改动这些部分。

## 18.4 AffectGPT 原始模型依据

AffectGPT 论文：

[Lian et al., AffectGPT: A New Dataset, Model, and Benchmark for Emotion
Understanding with Multimodal Large Language Models, ICML
2025](https://arxiv.org/abs/2501.16566)

重点参考论文 Section 3：

-   原始输入由 Video、Audio、Text 和用户指令组成；
-   视频与音频通过模态编码器提取特征；
-   使用 Q-Former-based 或 Attention-based Pre-fusion；
-   文本和指令被组织成 Prompt 后输入 LLM。

本方案建议第一阶段将 AMG 作为附加文本证据输入，不改变 AffectGPT
原有视频/音频编码和融合结构。

# 19. 一句话总结

**当前 AMG v2.1 已经完成了"固定全局本体 + 带权 CA/CE 关系 + 双层 Cue
准入 + 样本级证据图 +

Relation-aware Evidence Prompt，将正式 Cue

AffectGPT，同时保持原始多模态输入和九个目标数据集的 Zero-shot
协议不变。**

# 附录 A：当前 42 个 Cue 的完整清单

以下是对当前冻结 Cue 本体定义的简短摘要，用于 Prompt Adapter
的确定性描述映射。正式标注和边界判断仍应以仓库冻结定义文件为准，不能用本表替代完整操作规范。

## A.1 Text Cue（15 个）

  -----------------------------------------------------------------------------------------------------------------------
  Cue ID                                    简短含义                               关键边界
  ----------------------------------------- -------------------------------------- --------------------------------------
  `TXT_AFFECT_WORD_POSITIVE`                明确出现正向情绪词                     判断词汇是否出现，不直接判断整句极性

  `TXT_AFFECT_WORD_NEGATIVE`                明确出现负向情绪词                     判断词汇是否出现，不直接判断整句极性

  `TXT_EVALUATION_POSITIVE`                 对人物、事件、对象或结果作正向评价     不等同于正向情绪词

  `TXT_EVALUATION_NEGATIVE`                 对人物、事件、对象或结果作负向评价     不等同于愤怒或悲伤

  `TXT_NEGATION_PRESENT`                    存在语义性否定表达                     转折、不确定表达不能自动算否定

  `TXT_CONTRAST_PRESENT`                    存在明确转折或对比结构                 不能仅凭句子中有多个观点判断

  `TXT_INTENSIFIER_PRESENT`                 存在程度强化词                         必须是实际强化用法

  `TXT_UNCERTAINTY_HEDGE`                   存在削弱确定性的表达                   不能把所有观点表达都判为不确定

  `TXT_RHETORICAL_QUESTION`                 存在主要用于修辞而非索取信息的疑问     问号本身不足以判定

  `TXT_EXCLAMATION_INTERJECTION`            存在感叹词、感叹表达或表达性话语标记   标点本身不足以判定

  `TXT_DESIRE_NEED`                         明确表达愿望、希望、需求或目标         不从情境中臆测未表达的愿望

  `TXT_EXPLICIT_CAUSAL_ATTRIBUTION_SELF`    明确将事件/结果因果归因于自己          仅提及"I/我"不够

  `TXT_EXPLICIT_CAUSAL_ATTRIBUTION_OTHER`   明确将事件/结果因果归因于他人          仅提及他人不够

  `TXT_EXPLICIT_SUCCESS_OUTCOME`            明确表达成功、胜利、成就或目标达成     正向评价不自动等于成功结果

  `TXT_EXPLICIT_FAILURE_LOSS_OUTCOME`       明确表达失败、损失、拒绝或目标未达成   负向评价不自动等于失败结果

# 附录 B：全局边与样本级边的审计字段

## B.1 全局边字段

当前 `graph.json` 中的学习边保留了比 Prompt
所需更多的审计信息，典型字段包括：

  字段                                    含义
  --------------------------------------- ---------------------------------------
  `edge_id`                               全局边唯一 ID
  `source_id`                             源 Cue ID
  `target_id`                             目标 AppraisalState/EmotionConcept ID
  `source_index`                          Cue 在 42 维顺序中的索引
  `target_index`                          目标在对应矩阵中的索引
  `relation_type`                         CA 或 CE
  `weight`                                全局学习权重 W
  `sign`                                  正/负方向
  `support_sample_count`                  支持该边的样本数
  `support_group_count`                   支持该边的来源组数
  `fold_sign_consistency`                 跨 Fold 符号一致性
  `bootstrap_lower` / `bootstrap_upper`   Bootstrap 区间
  `dev_contribution`                      开发集贡献统计
  `admission_status`                      是否准入正式图
  `training_release_id`                   关系训练来源 Release
  `model_release_id`                      关系模型 Release
  `interpretation`                        当前语义为条件预测关联

## B.2 样本级关系字段

样本级局部关系保留：

-   `global_edge_id`：追溯到哪条全局 CA/CE 边；
-   `input_score`：当前 Cue 原始输入分数；
-   `contribution`：当前样本的 (q_iW\_{ij})；
-   `sign`：该贡献方向；
-   Fold/Bootstrap 稳定性信息；
-   图级暴露状态；
-   Prompt 级暴露状态。

因此，Prompt Adapter 不需要重新训练或重新计算
G1，只需要读取样本图中的贡献账本和稳定边映射，并执行 Prompt 级筛选。

# 附录 D：Prompt Adapter 实现验收清单

统一 Prompt Adapter 完成后，至少应逐项检查：

-   [ ] 所有任务使用同一种 AMG 证据结构；
-   [ ] 原始任务指令没有被覆盖；
-   [ ] 原始视频、音频、文本输入没有被替换或删除；
-   [ ] Cue Top-K 只从正式 CueEvidence 中选择；
-   [ ] Cue 分数使用 `source_calibrated_score`；
-   [ ] Prompt 不展示 CandidateCue 和 Deferred Cue；
-   [ ] Prompt 不把 Cue 分数称为情绪概率；
-   [ ] CA/CE 贡献来自账本中的 raw-score × global-weight；
-   [ ] 不使用校准分数重新计算贡献；
-   [ ] Prompt 不把 C 称为概率或因果效应；
-   [ ] 高层节点必须是正式 AppraisalEvidence/EmotionEvidence；
-   [ ] Prompt 级绝对贡献和正贡献覆盖率均重新计算；
-   [ ] Prompt 级覆盖不满足 0.90 时不暴露该高层假设；
-   [ ] 关系只来自正式 Cue、正式目标和稳定全局边；
-   [ ] AE 不被误生成；
-   [ ] 没有高层节点时允许 Cue-only Prompt；
-   [ ] 没有正式 CueEvidence 时正确回退原始 AffectGPT；
-   [ ] Prompt token 数由 AffectGPT tokenizer 实际测量；
-   [ ] 超预算时不截断原始多模态输入；
-   [ ] 每个 Prompt 都能追溯到对应样本图和 Release；
-   [ ] 完成 P0--P5 配对消融后再决定正式默认配置。
