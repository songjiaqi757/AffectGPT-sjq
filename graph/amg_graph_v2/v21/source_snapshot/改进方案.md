# AMG v2.1：Cue 阈值校准与证据准入策略改进方案

> **文档类型**：技术设计与实验实施方案\
> **适用项目**：AffectGPT-sjq / `graph/amg_graph_v2`\
> **目标版本**：AMG v2.1\
> **基线版本**：`amg_v2_reuse_b874bc7746edf155`\
> **核心原则**：冻结已有 Cue Student 和 G1
> 关系模型；改进校准、阈值选择、证据准入和可追溯性；不使用九个目标数据集的标签调参。\
> **状态说明**：本文是基于当前代码审查和前序方案形成的改进设计，不代表所有建议已经在仓库中实现，也不代表建议阈值已经通过实验验证。

## 1. 执行摘要

AMG v2 已经具备逐 Cue 概率校准、阈值搜索和样本级 CueEvidence
构建能力，但目前的阈值机制仍然偏向单层二值准入：每个 Cue 经过 Platt
Calibration 后，根据一个阈值决定是否创建正式证据节点。

这套机制存在几个需要解决的问题：

1.  Platt 校准器拟合和阈值搜索使用同一批 tune
    数据，可能导致阈值选择结果偏乐观。
2.  当前 `Precision >= 0.65`、预测数量至少 10、Wilson 下界至少 0.50
    的约束，对正式进入 AffectGPT Prompt 的证据可能不够严格。
3.  逐 Cue 阈值搜索没有充分考虑来源组相关性、阈值稳定性和 42 个 Cue
    同时筛选带来的选择偏差。
4.  单一 `active` 状态混合了"内部候选"和"可作为正式证据"的不同语义。
5.  当前关系模型使用连续 Cue 分数，而样本级图只显示达到阈值的
    Cue。未显示的 Cue 仍可能影响 CA/CE
    预测，造成预测贡献与可见证据之间的解释缺口。
6.  当前源域校准分数不能直接被解释为九个目标数据集上的真实后验概率。Zero-shot
    条件下不得使用目标数据集标签重新调阈值。

因此，建议将 Cue 阈值体系升级为：

**Group-aware OOF Calibration + Per-Cue Threshold Selection + Two-level
Admission + Group Bootstrap + Evidence Provenance Audit。**

具体原则：

-   不重新训练或覆盖现有正式 Cue Student。
-   不改变当前 G1 关系模型的原始连续 Cue 输入。
-   每个 Cue 独立校准、独立确定阈值，不使用统一 0.5。
-   Candidate 阈值用于内部候选与审计；Evidence 阈值用于正式 CueEvidence
    和 Prompt。
-   使用来源组级 Bootstrap 估计 Precision 不确定性和阈值稳定性。
-   对样本不足、校准不稳定或来源支持不足的 Cue 执行
    `deferred`，不为追求覆盖率而强行激活。
-   保留所有参与 CA/CE 预测的 Cue
    贡献记录，避免样本级图只展示部分证据却声称完整解释预测。
-   所有校准和准入策略在源域开发数据上确定并冻结，九个目标数据集只用于最终
    Zero-shot 测评。

## 2. 当前 AMG v2 实现与基线事实

本节记录当前 Release 的实现情况。它们是基线描述，不应与 v2.1
的建议配置混淆。

### 2.1 当前 Cue 校准与阈值逻辑

当前流程可概括为：

\[ X `\xrightarrow{Student}`{=tex} q_j `\xrightarrow{Platt}`{=tex}
p_j\^{cal} `\xrightarrow{Threshold}`{=tex} CueEvidence \]

其中：

-   (q_j)：第 (j) 个 Cue Student 输出的原始连续分数；
-   (p_j\^{cal})：经过逐 Cue Platt Calibration 的分数；
-   (t_j)：当前 Cue 的准入阈值。

当前校准过程使用每个 Cue 的有效标注样本拟合 Platt 参数：

\[ p\_{ij}\^{cal} = `\sigma`{=tex}`\left`{=tex}(a_j
`\operatorname{logit}`{=tex}(q\_{ij})+b_j`\right`{=tex}) \]

当前阈值搜索以最大化 Recall 为目标，同时满足若干约束：

\[ t_j\^\* = `\arg`{=tex}`\max`{=tex}\_t Recall_j(t) \]

约束包括：

-   Precision 不低于 0.65；
-   预测正样本数量至少为 10；
-   Wilson Precision 下界至少为 0.50。

当前校准拟合的正、负样本最低数量要求为 20。当前 Release 中 42 个 Cue 有
39 个进入 active，3 个 Cue 因监督支持不足而 deferred：

-   `AUD_PAUSE_FREQUENT`
-   `AUD_LAUGHTER_PRESENT`
-   `AUD_CRYING_SOBBING_PRESENT`

这些是当前版本的实际策略结果，不代表 39 个 Cue
已经通过更严格的独立证据审计。

### 2.2 当前阈值与关系模型的关系

当前 `runtime.py` 中，关系模型使用原始 Cue 分数构建输入，逻辑近似为：

``` python
qm = np.where(av, q, 0.)

za = qm @ self.model["CA"] + self.model["CA_bias"]
zce = qm @ self.model["CE"] + self.model["CE_bias"]
```

Cue 阈值主要决定 CueEvidence 节点是否被暴露，而不是直接决定原始 Cue
分数是否参与 CA/CE 计算。

因此：

-   一个 Cue 可能低于证据阈值；
-   它可能不会创建正式 CueEvidence 节点；
-   但它的原始分数仍可能参与 CA/CE 关系预测。

这意味着"可见证据图"不一定完整覆盖"模型预测所使用的输入贡献"。v2.1
必须明确记录这两者之间的差别，不能将隐藏贡献误写成已展示证据的支持。

### 2.3 当前版本应保留的资产

v2.1 不应覆盖当前 Release。建议将当前版本作为 T0 基线，完整保留：

-   三个正式 Cue Student checkpoint；
-   Cue Student 推理配置及缓存身份信息；
-   G1 CA/CE 关系参数；
-   当前校准器和阈值文件；
-   当前全局图及样本级图 Schema；
-   当前 Release Manifest、数据划分、哈希和审计报告。

**本次改进不是重做 Cue Student，也不是推翻 G1，而是改进 G1
周围的校准与证据准入层。**

## 3. 设计目标、非目标与基本原则

### 3.1 设计目标

v2.1 需要实现以下目标：

1.  **校准可信**：校准器和阈值选择不能直接利用同一批样本的拟合内结果。
2.  **逐 Cue 自适应**：42 个 Cue 独立确定校准器、阈值和准入状态。
3.  **高置信证据**：进入 Prompt 的 Cue 应满足更严格的
    Precision、来源支持和稳定性要求。
4.  **保留召回信息**：低于正式证据阈值但仍有一定价值的 Cue
    可以作为内部候选保存，不必全部丢弃。
5.  **统计稳健**：考虑同源视频、同一说话人、同一 Session 等样本相关性。
6.  **解释一致**：样本级图能够追踪所有影响关系预测的 Cue 贡献。
7.  **模型兼容**：默认不改变 Student 和 G1 的输入分布。
8.  **Zero-shot
    合规**：九个目标数据集不参与阈值拟合、阈值选择、校准器选择和参数调整。
9.  **可复现**：所有阈值、校准参数、数据划分、来源组、随机种子和模型哈希均可审计。

### 3.2 非目标

本次不建议同时开展以下改动：

-   不重新训练或覆盖正式 Cue Student。
-   不直接更改 G1 的 CA/CE 权重。
-   不在推理时简单将低于阈值的 Cue 分数置零。
-   不强制让 42 个 Cue 全部 active。
-   不为了提高 Cue 覆盖率而降低所有 Cue 的统一门槛。
-   不引入 GNN、EmotionFamily 强制层级或额外 Cue 模型。
-   不根据九个目标数据集的测试结果反向调整阈值。
-   不将校准分数解释为跨域、跨数据集都具有相同含义的真实概率。

### 3.3 核心设计原则

**原则 A：模型输入与证据暴露分离。**

原始连续 Cue
分数用于关系模型；校准分数用于证据准入。除非另行训练和验证，不得让准入阈值改变
G1 的输入。

**原则 B：候选不等于证据。**

Candidate 是内部分析对象；Evidence Active 才是可以作为正式证据节点暴露给
AffectGPT 的对象。

**原则 C：数据不足时拒绝确定性输出。**

`deferred` 是有效的模型状态，不是系统失败。少数类 Cue
不应因为希望增加图密度而被强制激活。

**原则 D：阈值选择和阈值评估分开。**

阈值在开发数据上选择；独立审计集只用于冻结策略后的验证，不再用于反复调参。

## 4. 数据与划分协议

阈值改进的前提是数据角色清楚。不能只增加 Bootstrap
次数，却不检查样本来源是否真正独立。

### 4.1 先审计当前数据角色

当前 Release
中使用了内部关系训练、校准/调参、内部评估及预留数据。现有报告中还指出，部分历史验证数据曾参与
Student 选模。因此，必须逐条检查：

-   样本 ID 是否重复；
-   `group_id` 是否一致；
-   原始视频、音频、图像或文本来源是否重复；
-   Speaker、Session、Conversation 是否跨划分；
-   精确 SHA256 是否跨划分；
-   可检测的近重复是否跨划分；
-   该样本是否参与过 Student 训练；
-   该样本是否参与过 Student 选模；
-   该样本是否参与过关系模型训练；
-   该样本是否参与过校准器或阈值选择。

不能仅凭数据文件名为 `validation` 或 `test` 就认定其完全独立。

### 4.2 推荐的数据角色

  ---------------------------------------------------------------------------
  数据角色                用途                       是否允许调阈值
  ----------------------- -------------------------- ------------------------
  Student 原训练集        已有 Cue Student 训练      否

  Relation Train          G1 CA/CE 关系学习          否

  Calibration Development OOF 校准和策略开发         是

  Locked Audit            冻结策略后的独立人工审计   否

  Internal Evaluation     既有内部评估及回归比较     不作为新策略反复调参集

  九个目标数据集          最终 Zero-shot 测评        绝对不允许
  ---------------------------------------------------------------------------

如果当前 300 条人工审计预留样本确实具有完整 Cue 标注，且未参与 Student
训练、选模、关系训练、校准或阈值选择，可以作为 Locked Audit
的候选。但在确认其独立性、标注质量和样本覆盖之前，不能直接称为独立审计集。

### 4.3 OOF Student 问题必须单独核验

这里有两个不同的交叉拟合问题：

1.  **Cue Student OOF**：Student 是否对其训练样本产生了样本内预测。
2.  **Platt Calibration
    OOF**：校准器是否在未参与自身拟合的样本上产生校准分数。

二者不能混为一谈。

如果 Calibration Development 样本从未参与 Student
参数训练，只参与过模型选型，那么它们不是 Student
训练内预测，但仍存在历史模型选择曝光，需要如实记录。

如果 Calibration Development 样本与 Student
训练样本重叠，则需要为校准用途生成 Student OOF
预测，或另行建立真正未参与 Student 训练的校准数据。

这不意味着必须替换正式 Student：

-   正式推理 Student 保持不变；
-   只在必要时建立辅助 OOF Student 预测；
-   辅助 OOF 结果用于校准策略研究；
-   是否需要改变正式推理 Student，必须由分布一致性实验决定。

### 4.4 Group 的定义

Group 应尽可能表示真正的共同来源，而不是简单的行 ID。

建议优先级：

1.  原始视频/音频/媒体来源 ID；
2.  原始采集 Session；
3.  Conversation / Speaker；
4.  精确媒体 SHA256；
5.  可检测近重复关系；
6.  已知的上游数据来源关系。

同一来源组的样本必须放在同一折中。

如果缺少来源元数据，必须在报告中说明分组局限。精确 SHA256
去重不能替代完整的来源独立性审计。

### 4.5 标注缺失与负样本

Cue 标签必须区分：

-   正样本；
-   明确负样本；
-   未标注/未知；
-   不适用；
-   模态不可用。

未知标签不能当作负样本。所有校准、Precision、Recall 和 Bootstrap
计算必须应用有效标注 mask。

## 5. 第一阶段：Group-aware OOF Platt Calibration

### 5.1 为什么保留 Platt

当前每个 Cue 都是独立二分类任务，且可用于校准的样本量有限。Platt
参数较少，适合当前阶段。

本方案不建议立即换成复杂的 Isotonic Regression。Isotonic
在样本量不足时可能产生不稳定的阶梯式映射。

对 Cue (j)：

\[ z\_{ij}=`\operatorname{logit}`{=tex} `\left`{=tex}(
`\operatorname{clip}`{=tex}(q\_{ij},`\epsilon`{=tex},1-`\epsilon`{=tex})
`\right`{=tex}) \]

Platt 映射为：

\[ p\_{ij}\^{cal} = `\sigma`{=tex}(a_jz\_{ij}+b_j) \]

其中：

-   (q\_{ij})：Student 原始输出；
-   (a_j)：校准斜率；
-   (b_j)：校准截距；
-   (p\_{ij}\^{cal})：源域校准分数。

### 5.2 Group-aware OOF 校准

在 Calibration Development 内按 Group 划分折。对第 (k) 折：

\[ (a_j^{(-k)},b_j^{(-k)}) = `\operatorname{PlattFit}`{=tex}(D\_{-k,j})
\]

在留出的第 (k) 折上计算：

\[ p\_{ij}\^{OOF} = `\sigma`{=tex}(a_j^{(-k)}z\_{ij}+b_j^{(-k)}) \]

最终得到每个 Cue 的 OOF 校准分数。任何样本的 OOF
校准分数都不能由使用该样本标签拟合的校准器产生。

建议使用 `StratifiedGroupKFold` 或等价的 Group-aware
分层划分，但必须先检查每个 Cue 的正负来源组是否足以支持五折。

如果五折不可行：

-   可在组数量和类别支持允许时降为三折；
-   不能为了凑折而拆开同一来源组；
-   仍然无法可靠校准时，将该 Cue 标记为
    `deferred_insufficient_calibration_support`。

### 5.3 OOF 不等于阈值评估完全无偏

OOF Platt 解决的是校准器对自身训练样本的拟合内评估问题，但如果在同一批
OOF 分数上搜索阈值，再用同一批数据报告最终
Precision，阈值选择本身仍可能产生乐观偏差。

因此建议采用两层评估：

**策略评估：Nested Group CV**

-   外层 Group Fold：用于评估整套"校准 + 阈值选择"策略。
-   内层 Group OOF：在外层训练部分生成校准分数并选择阈值。
-   在外层留出组上评估固定阈值的 Precision、Recall、覆盖率和稳定性。

这样可以估计阈值选择流程在未见来源组上的表现。

**最终策略拟合**

-   使用全部 Calibration Development 生成最终 OOF 校准分数；
-   在 OOF 分数上确定最终 Candidate / Evidence 阈值；
-   在全部开发数据上重新拟合部署用 Platt 参数；
-   使用 Locked Audit 检查最终部署校准器和阈值的真实表现。

需要检查"OOF
校准器"和"全量开发数据最终校准器"的分数分布是否存在明显偏移。最终部署表现以
Locked Audit 为准。

### 5.4 校准器准入规则

每个 Cue 单独判断，不应强制所有 Cue 都使用 Platt。

建议至少记录：

-   有效正样本数；
-   有效负样本数；
-   正样本来源组数；
-   负样本来源组数；
-   OOF Brier Score；
-   OOF Log Loss；
-   OOF ECE；
-   Reliability Diagram；
-   PR-AUC；
-   Platt slope / intercept；
-   原始分数与校准分数的比较。

建议初始数据支持门槛：

  条件             初始建议
  -------------- ----------
  有效正样本数         ≥ 30
  有效负样本数         ≥ 30
  正样本来源组         ≥ 10
  负样本来源组         ≥ 10

这些是实验起点，不是统计学上的充分性保证。是否可校准仍应由 OOF
表现和来源组支持决定。

校准策略：

-   Platt 在 OOF 上表现稳定且优于原始分数：使用 Platt。
-   原始分数已具有可接受的 OOF 校准表现：可在预先规定的规则下使用
    Identity Calibration。
-   Platt 斜率方向异常、结果不稳定或 OOF 校准质量变差：不强行使用
    Platt。
-   样本支持不足：Deferred，不将原始 Student 分数冒充校准概率。

不要在 Platt 校准器中随意使用
`class_weight="balanced"`。类别加权可能改变输出概率所对应的先验分布，造成概率偏移。若确实需要加权，应另行进行概率校准和独立验证。

### 5.5 概率校准指标

  -----------------------------------------------------------------------------
  指标                    目的                         注意事项
  ----------------------- ---------------------------- ------------------------
  Brier Score             概率误差                     越低越好

  Log Loss                概率预测质量                 对极端错误概率较敏感

  ECE                     校准偏差                     对分箱方式和样本量敏感

  Reliability Diagram     观察预测概率与实际频率关系   必须标注每个分箱样本量

  PR-AUC                  排序能力                     不是概率校准指标

  ROC-AUC                 排序能力                     类别极不平衡时不能替代
                                                       PR-AUC
  -----------------------------------------------------------------------------

ECE 应采用固定、可复现的分箱策略，并报告每箱样本量。低样本 Cue
不应仅凭一个 ECE 数值认定校准可靠。

## 6. 第二阶段：逐 Cue 双层阈值策略

### 6.1 为什么不能只有一个阈值

一个阈值同时承担两项不同任务：

-   保留尽可能多的潜在 Cue；
-   保证进入 Prompt 的 Cue 足够可靠。

这两项目标存在冲突。

因此 v2.1 将阈值拆成：

\[ t_j^{candidate}`\leq `{=tex}t_j^{evidence} \]

其中：

-   Candidate：内部候选准入；
-   Evidence：正式证据准入。

### 6.2 Candidate Admission

Candidate
层用于内部候选分析、图覆盖率统计和关系贡献审计，不直接作为正式证据传给
AffectGPT。

建议初始实验约束：

  指标                                   建议起点
  -------------------------------- --------------
  Precision 点估计                         ≥ 0.65
  Group Bootstrap Precision 下界     ≥ 0.55～0.60
  预测样本数                                 ≥ 30
  预测来源组数                               ≥ 20

阈值选择：

\[ t_j\^{candidate} = `\arg`{=tex}`\max`{=tex}\_t Recall_j(t) \]

满足 Candidate 的全部约束。

### 6.3 Evidence Admission

Evidence 层用于创建正式 CueEvidence 节点，并允许进入正式 Prompt。

建议初始实验约束：

  指标                                       建议起点
  -------------------------------- ------------------
  Precision 点估计                             ≥ 0.80
  Group Bootstrap Precision 下界               ≥ 0.70
  预测样本数                         ≥ 50，必要时提高
  预测来源组数                                   ≥ 30
  Bootstrap 准入稳定率                         ≥ 0.80

阈值选择：

\[ t_j\^{evidence} = `\arg`{=tex}`\max`{=tex}\_t Recall_j(t) \]

约束：

\[ Precision_j(t)`\geq `{=tex}P\_{`\min`{=tex}}\^{evidence} \]

\[ LCB_j^{group}(t)`\geq `{=tex}L\_{`\min`{=tex}}^{evidence} \]

\[ N\_{pred,j}(t)`\geq `{=tex}N\_{`\min`{=tex}}\^{evidence} \]

\[ N\_{groups,j}(t)`\geq `{=tex}G\_{`\min`{=tex}}\^{evidence} \]

\[ Stability_j(t)`\geq `{=tex}S\_{`\min`{=tex}}\^{evidence} \]

这里的 0.80、0.70、50、30 和 0.80
都是待验证的初始配置，不应在没有实验结果前写成已证明的最优阈值。

### 6.4 阈值搜索实现

对每个 Cue：

1.  仅使用有效标注和有效预测；
2.  在 OOF 校准分数的唯一值或预先规定的候选网格上搜索；
3.  对每个阈值计算 TP、FP、FN、Precision、Recall、预测数和来源组数；
4.  计算 Group Bootstrap Precision 下界；
5.  计算阈值稳定性；
6.  删除不满足约束的阈值；
7.  在剩余阈值中选择 Recall 最大者；
8.  如果没有任何阈值满足条件，返回 Deferred。

在单调分数阈值下，最大化 Recall
通常对应于选择仍满足全部约束的最低阈值。实现中应显式处理并列分数和并列指标，保证结果确定、可复现。

不能对没有预测正样本的阈值计算出虚假的高
Precision。预测数量为零时，该阈值必须视为不满足准入条件。

### 6.5 为什么不直接最大化 F1

本项目的 Cue 不只是分类输出，也会作为证据进入多模态大模型 Prompt。

错误激活的 Cue
可能造成错误解释，尤其是把外观、语速、表情等表层线索误当成心理事实。

因此，Evidence 层应优先控制 Precision，再在约束内最大化
Recall，而不是单纯最大化 F1。

F1 可以作为报告指标，但不应成为正式证据准入的唯一目标。

## 7. 第三阶段：Group Bootstrap 与阈值稳定性

### 7.1 为什么使用 Group Bootstrap

普通 Wilson
区间把每条样本视为独立观测。若多个样本来自同一视频、同一说话人或同一
Session，样本之间可能相关，普通样本级区间可能低估不确定性。

Group Bootstrap 的基本单位应是来源组：

1.  从来源组集合中有放回地抽取组；
2.  每个抽中的组带入其全部样本；
3.  在重采样数据上计算 Precision；
4.  重复多次；
5.  使用 Precision 分布的低分位数作为置信下界。

\[ LCB_j(t) = Q\_{0.025} `\left`{=tex}(
Precision_j\^{(1)}(t),`\ldots`{=tex}, Precision_j\^{(B)}(t)
`\right`{=tex}) \]

建议初始重复次数：

\[ B=1000 \]

可在计算资源允许时增加到 2000，并固定随机种子。

### 7.2 固定阈值置信区间与阈值稳定性是两件事

必须分别报告：

**A. 固定阈值的 Precision 不确定性**

对已经选定的阈值 (t_j)，在每次 Group Bootstrap 中计算
Precision，得到其置信区间。

**B. 阈值选择稳定性**

每次 Bootstrap 都重新搜索阈值：

\[ t_j\^{(b)} = `\arg`{=tex}`\max`{=tex}\_t Recall_j\^{(b)}(t) \]

记录：

-   阈值中位数；
-   阈值四分位区间；
-   阈值 95% 区间；
-   满足准入约束的 Bootstrap 比例；
-   每次是否存在有效准入阈值。

Evidence 层建议初始要求至少 80% 的 Bootstrap 重采样仍满足准入条件。

如果某个 Bootstrap
样本没有足够预测正例、没有足够来源组或没有任何可行阈值，应记为该次准入失败，不能简单丢弃后再计算成功比例。

### 7.3 42 个 Cue 的多重筛选问题

逐 Cue 选择阈值意味着同时进行 42 次策略选择。每个 Cue 的 95%
置信区间并不自动意味着 42 个 Cue 的整体结论具有 95% 同时覆盖率。

建议：

-   运行时准入仍按预先规定的逐 Cue 规则执行；
-   报告中明确逐 Cue 区间是边际区间；
-   如需作出"所有 Cue 整体可靠"的统计性结论，应增加多重比较控制，例如
    Holm 校正或同时 Bootstrap；
-   不要把逐 Cue 的边际置信下界描述为全体 Cue 的同时置信保证。

### 7.4 Group Bootstrap 的前置条件

如果每个 group 实际只有一条样本，Group Bootstrap 会退化为普通样本
Bootstrap。

因此必须先报告：

-   group 总数；
-   每组样本数分布；
-   每个 Cue 的正样本组数；
-   每个 Cue 的负样本组数；
-   每个阈值下的预测正例组数；
-   同源样本是否跨折。

不能仅因为代码调用了 Group Bootstrap，就宣称已经解决来源相关性。

## 8. 第四阶段：Runtime 的状态和证据语义改造

### 8.1 新增 Cue 状态

建议将当前状态扩展为：

  状态                含义                                 正式 CueEvidence          正式 Prompt
  ------------------- ---------------------------------- ------------------ --------------------
  `unavailable`       模态或 Cue 输出不可用                              否                   否
  `not_requested`     本次任务未请求该 Cue                               否                   否
  `invalid_score`     输出缺失、非有限值或超出有效范围                   否                   否
  `deferred`          校准或统计支持不足                                 否                   否
  `below_candidate`   未达到 Candidate 阈值                              否                   否
  `candidate_only`    达到 Candidate，未达到 Evidence                    否                   否
  `evidence_active`   达到 Evidence 阈值                                 是   满足任务规则时可以

建议保留独立字段 `calibration_status` 和
`admission_status`，不要把所有状态都塞入一个难以解释的字符串。

### 8.2 四种 Mask 必须区分

建议至少区分：

\[ M\_{available} \]

表示 Cue 分数是否有效、模态是否可用。

\[ M\_{model} \]

表示该 Cue 是否允许参与 CA/CE 关系模型计算。

\[ M\_{candidate} \]

表示该 Cue 是否达到 Candidate 阈值。

\[ M\_{evidence} \]

表示该 Cue 是否达到 Evidence 阈值，可以创建正式 CueEvidence。

如果有 Prompt 任务保护，还应增加：

\[ M\_{prompt} \]

表示该正式证据是否适合当前任务类型并被实际序列化。

这些 Mask 的含义不能互相替代。

### 8.3 保持 G1 输入分布不变

v2.1 的默认策略：

-   原始 Student 分数 (q) 保持不变；
-   关系模型仍使用当前版本约定的可用性 Mask；
-   Platt 分数仅用于阈值和证据准入；
-   Candidate / Evidence 阈值不直接改变 G1 输入；
-   不在推理阶段简单把 below-threshold 分数置零。

这样可以把"阈值策略改进"和"关系模型输入改造"分成两个独立实验。

如果未来希望只有 Evidence Active Cue
才能参与关系预测，必须另建模型实验：

1.  定义训练时相同的 Cue Mask 规则；
2.  重新训练或至少重新校准 CA/CE；
3.  评估输入分布变化；
4.  与原始 G1 进行配对比较。

不能只在推理阶段置零，然后仍然声称使用的是原 G1 模型。

### 8.4 解决隐藏 Cue 贡献与可见图不一致

这是 v2.1 必须明确解决的解释问题。

当前 G1 可能使用所有有效 Cue 的连续分数，但样本级图只显示 Evidence
Active Cue。这样会出现：

-   某个 below-candidate Cue 未显示；
-   它仍然影响 CA/CE logits；
-   最终 EmotionEvidence 可能受到该隐藏贡献影响；
-   样本级图却看起来只有已显示 Cue 在支持该 Emotion。

建议建立完整的贡献审计账本。

对线性关系模型，至少记录每个 Cue 对每个输出维度的贡献：

\[ Contribution\_{j,k}=q_jW\_{j,k} \]

并保留：

-   Cue ID；
-   原始分数；
-   可用性；
-   admission status；
-   对 CA/CE 各输出的贡献；
-   正负方向；
-   贡献大小；
-   是否被样本级图暴露；
-   是否进入 Prompt。

推荐将样本级信息分为：

1.  `CueSignal`：所有参与关系模型的有效 Cue 信号，属于内部审计层；
2.  `CueEvidence`：通过 Evidence Admission 的正式证据；
3.  `CandidateCue`：通过 Candidate、未通过 Evidence 的内部候选；
4.  `RelationContribution`：Cue 对 CA/CE 输出的具体贡献；
5.  `AppraisalEvidence` /
    `EmotionEvidence`：关系分支产生的输出及其来源状态。

正式 Prompt 默认只使用 `evidence_active` Cue。Candidate 只用于离线审计。

对于受未准入 Cue 显著影响的 Appraisal / Emotion 输出，应标记为
`model_only` 或 `partially_supported`，不能伪装成已展示 Cue
的完整证据结论。

如果需要让 EmotionEvidence 只由正式证据 Cue
支持，可以考虑单独计算证据子集分支，但这会改变 G1
的有效输入，必须作为独立训练/校准实验验证，不能直接替换现有 G1 结果。

### 8.5 模态可用性

不要因为一个 Cue 推理失败就把整个模态标为不可用。

建议分开保存：

-   `modality_available`；
-   `cue_score_valid`；
-   `cue_requested`；
-   `cue_prediction_success`。

模态级可用性应来自输入和模态处理状态；Cue 级有效性应来自具体 Cue
的输出状态。

## 9. 独立人工审计与标注质量

### 9.1 300 条预留样本的使用原则

如果当前预留的 300 条样本满足以下条件，可以作为 Locked Audit 候选：

-   未参与 Student 训练；
-   未参与 Student 选模；
-   未参与关系模型训练；
-   未参与 Platt 拟合；
-   未参与阈值选择；
-   有完整、可追溯的 Cue 人工标签；
-   来源组与开发数据没有不可接受的重叠。

必须先核验这些条件。

300 条样本不一定足以验证全部 42 个 Cue。每个 Cue
的有效预测正例数量、来源组数和置信区间都需要单独报告。

### 9.2 人工标注协议

Cue 是可观察线索，不等同于潜在心理状态。人工审计应明确：

-   Cue 的操作性定义；
-   正例与负例判定标准；
-   无法判断的情形；
-   模态不可用的情形；
-   是否允许多 Cue 同时存在；
-   标注者是否能看到模型预测；
-   分歧如何裁决。

建议对审计样本进行双人独立标注，并对分歧进行
adjudication。报告标注一致性和每个 Cue 的有效标注量。

不能把"标注一致"直接等同于"心理事实真实"。本方案评估的是模型预测与操作性
Cue 标注的一致程度。

### 9.3 审计抽样与 Precision 估计

如果审计集是自然随机抽样，Precision 可以按样本设计直接估计。

如果为了提高稀有 Cue
的审计效率而过采样模型预测正例或特定分数区间，则必须记录抽样概率，并使用设计权重估计部署分布下的
Precision。

否则，过采样数据上计算出的 Precision 不能直接代表自然部署流量中的 PPV。

### 9.4 审计集不得反复调参

Locked Audit 只用于冻结策略后的最终验证。

如果审计结果不满足目标：

-   记录失败；
-   返回开发数据设计下一轮策略；
-   必要时收集新的独立审计数据；
-   重新冻结版本；
-   不得在同一审计集上反复调整阈值，再把调整后的结果称为独立验证。

## 10. Zero-shot 与跨数据集约束

### 10.1 校准域与目标域

本方案的校准和阈值开发使用源域数据。九个目标数据集不参与：

-   Platt 拟合；
-   校准器选择；
-   Candidate 阈值选择；
-   Evidence 阈值选择；
-   Precision 门槛选择；
-   Prompt 策略选择；
-   关系权重调整。

这才符合目标数据集 Zero-shot 评测要求。

### 10.2 不要过度解释校准概率

源域校准分数表示模型在源域校准数据上学到的概率映射。

跨域后，Cue 的类别先验、输入分布和标注习惯可能变化。因此不能直接声称：

\[ p_j\^{cal}=0.8 \]

就代表九个目标数据集上该 Cue 有 80% 的真实发生概率。

建议在代码、日志和文档中使用 `source_calibrated_score`
等名称，避免无条件称为真实概率。

### 10.3 目标域分布偏移

可以在不使用目标标签的条件下报告：

-   Cue 原始分数分布；
-   模态可用率；
-   Candidate / Evidence 覆盖率；
-   输入分布偏移诊断；
-   `deferred` 比例；
-   样本级图空图率。

但不能根据目标集的真实情绪标签或 Cue 标签调节阈值。

若发现严重分布偏移，应该报告适用性限制或触发保守回退，而不是使用测试集标签进行再校准。

## 15. Prompt 与任务类型的准入规则

正式 Evidence Active Cue 也不意味着任何任务都应该使用它。

建议保持任务保护：

  任务类型                CueEvidence              Appraisal             Emotion 候选
  ------------------ ---------------- ---------------------- ------------------------
  Discrete Emotion               可用   可用但需标记不确定性                     可用
  Polarity                       可用               谨慎使用   默认不提供离散情绪候选
  Open Vocabulary      可用作辅助证据             可用作假设       不限制自由词汇表达

Prompt 必须说明：

-   Cue 是模型检测到的可观察线索；
-   Appraisal 是模型推断的评价假设；
-   Emotion 是模型候选，不是确定心理事实；
-   模型仍需检查原始多模态输入；
-   不得因图中没有某个 Cue 就断言该线索不存在；
-   不得把 Candidate 或 Deferred Cue 当成正式证据；
-   不得把统计关联描述成心理因果关系。

如果正式 Emotion 输出受到未准入 Cue 的显著影响，必须标记为 `model_only`
或 `partially_supported`，不应伪装成完全由可见证据支持。

## 16. 自动化测试与验收标准

v2.1 不能只靠人工查看 JSON 判断正确，应增加自动化测试。

### 16.1 校准测试

-   每个 Cue 的校准只使用有效标签。
-   未知标签不会被当作负样本。
-   OOF 样本不参与对应校准器的拟合。
-   同一来源组不跨折。
-   不满足样本支持的 Cue 返回 Deferred。
-   Platt 斜率异常时不会静默准入。
-   校准分数均为有限值且在合法范围内。

### 16.2 阈值测试

-   Evidence 阈值不低于 Candidate 阈值。
-   无预测正例的阈值不能被判定为满足 Precision。
-   预测数量不足时不能准入。
-   来源组数量不足时不能准入。
-   Bootstrap 失败重复不能被静默丢弃。
-   Bootstrap 准入稳定率不足时 Evidence 必须 Deferred。
-   相同数据、配置和种子必须产生相同策略文件。

### 16.3 Runtime 测试

-   `unavailable` 不创建正式证据。
-   `not_requested` 不创建正式证据。
-   `invalid_score` 不创建正式证据。
-   `deferred` 不创建正式证据。
-   `candidate_only` 不进入正式 Prompt。
-   `evidence_active` 才能创建正式 CueEvidence。
-   模态可用性与 Cue 级预测有效性分离。
-   Candidate / Evidence 阈值不改变原始 G1 输入。
-   每个影响 CA/CE 的有效 Cue 都有贡献审计记录。
-   未展示贡献不能被错误标记为可见证据支持。
-   任务类型保护持续有效。
-   无图或无可靠证据时能够安全回退到原始 AffectGPT。

## 19. 最终推荐架构

AMG v2.1 的推荐 Cue 流程：

``` text
Original Multimodal Input
        |
        v
Frozen Cue Students
        |
        +------------------------------+
        |                              |
        v                              v
Raw Continuous Cue Scores       Availability / Validity
        |                              |
        |                              v
        |                       Group-aware OOF Calibration
        |                              |
        |                              v
        |                       Per-Cue Calibrated Scores
        |                              |
        |                    +---------+----------+
        |                    |                    |
        |                    v                    v
        |              Candidate Threshold   Evidence Threshold
        |                    |                    |
        |                    v                    v
        |              Candidate Only       Evidence Active
        |                    |                    |
        |                    v                    v
        |              Internal Audit       Formal CueEvidence
        |                                         |
        v                                         v
Frozen G1 CA / CE Relation Model             Prompt Evidence
        |
        v
Relation Contribution Ledger
        |
        v
Sample-level Evidence Graph
        |
        v
Task-aware Evidence Gating
        |
        v
AffectGPT
```

该架构中：

-   原始连续 Cue 分数继续服务于当前 G1；
-   校准分数服务于证据准入；
-   Candidate 不进入正式 Prompt；
-   Evidence Active 才创建正式 CueEvidence；
-   关系贡献账本负责解释 G1 使用了哪些 Cue；
-   对未准入 Cue 的影响必须保留审计信息；
-   最终输出仍由 AffectGPT 结合原始多模态内容完成判断。

## 20. 最终结论与决策

综合当前 AMG v2 的实现和前序讨论，建议将 v2.1 的核心工作限定为以下五项：

1.  **Group-aware OOF Platt
    Calibration**：解决校准器拟合内评估和阈值选择偏差。
2.  **Nested Group
    CV**：评估完整的校准与阈值选择流程，而不只评估一个拟合后的阈值。
3.  **双层 Cue Admission**：Candidate 负责保留潜在信息，Evidence
    负责正式证据可靠性。
4.  **Group Bootstrap + Threshold
    Stability**：控制来源组相关性和阈值不稳定问题。
5.  **Runtime Provenance Audit**：解决原始 Cue 分数参与
    G1、但未被样本级证据图展示的问题。

其中最重要的工程决策是：

-   保留正式 Cue Student；
-   保留 G1 CA/CE 权重和原始输入分布；
-   不强制 42 个 Cue 全部 active；
-   不把校准概率等同于目标域真实概率；
-   不用九个目标数据集的标签调阈值；
-   不把 Candidate 当成正式证据；
-   不让未展示的 Cue 贡献冒充已展示证据的支持。

**最终目标不是让样本级图尽可能稠密，而是让每个正式 CueEvidence
都有可量化、可审计、可复现的准入依据，并且让它对 AffectGPT
的下游判断产生真实的净收益。**

在完成校准与准入策略验证之前，不建议继续增加 Cue
节点、关系类型或更复杂的图神经网络。先证明现有 Cue Student 和 G1
关系模型产生的证据足够可靠，再验证这些证据是否真正改善九个 Zero-shot
数据集上的 AffectGPT 表现。
