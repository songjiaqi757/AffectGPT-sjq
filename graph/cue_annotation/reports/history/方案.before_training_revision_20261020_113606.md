## 1. 固定协议、输出层与成本

### 1.1 API与Prompt

接口：`https://maas.qianwenaiapi.com/compatible-mode/v1/chat/completions`；模型：`qwen3.8-omni-flash`。生成参数固定为 `temperature=0`、`reasoning_effort=none`、`response_format={"type":"json_object"}`、`max_tokens=3072`、`stream=false`、`modalities=["text"]`。并发/RPM/TPM属于运行配置，不改变Prompt和Cue定义。

| 模态 | Prompt SHA256 |
|---|---|
| text | `46a44e9c46a2d24a48a916e7a02211a6225caff10d66ab2d8eaad08f09536de6` |
| audio | `cab586cf3804d378916322929e027a59c0a19122e0ac65dbf4d7da545657b500` |
| visual | `9acbba0d5ec71bbf18906c924c1a93198d011646f1dedb48fb566b57589fb4cd` |

每个响应必须含唯一的 `sample_id`、`modality`、`labels`，对应模态的Cue恰好出现一次；每项仅含 `state`、`evidence_note`。状态仅positive/negative/uncertain/unobservable，positive、uncertain、unobservable均须有非空证据。还检查返回模型名称、`finish_reason=stop`与JSON/schema完整性。缺字段、解析失败和输出截断作为任务失败处理，不自动补negative。

```json
{"sample_id":"sample_id","modality":"visual","labels":{"VIS_SMILE_PRESENT":{"state":"negative","evidence_note":""}}}
```

此例仅说明结构；实际视觉响应须包含全部10个视觉Cue，另外两种模态分别为15和17项。本体ID固定为 `cue_ontology_v1.2`。

### 1.2 API原始判断与训练监督层

`teacher_raw/`保存每次API响应/错误及请求哈希；`annotations/`保存通过校验、可能附带明确质量处理的最终模态记录；`inputs/`保存实际输入、媒体和请求哈希。原`media/audio/`、`media/video/`为完整API输入副本，已按第15节清理；原始dataset和历史输入元数据保留，后续输入按需恢复。旧试标的8张浏览缩略图不属于API帧输入。

一般映射：positive→y=1/mask=1；negative→y=0/mask=1；uncertain/unobservable→y空/mask=0。失败/待处理只在导出层使用unlabeled→y空/mask=0，不能将其解释为模型判断“看不见”或“没有”。

`VIS_TEARING_PRESENT`与其他Cue采用相同处理：保留API原始state和evidence_note，positive→y=1/mask=1，negative→y=0/mask=1，uncertain/unobservable→y空/mask=0。按用户2026-10-20最新要求，已取消流泪专用门控，902条原始阳性恢复为positive，不添加逐样本人工确认或批量指定标记。此前200条中途快照和902条全量候选的屏蔽属于历史处理，现已撤销；原始模型响应不变。

## 2. Cue 语义与状态规范

### 2.1 样本级语义

每个 Cue 表示：

> 在该样本实际可观察的范围内，是否存在可复核证据支持这个 Cue。

它不表示完整原始视频在所有时刻都不存在该 Cue，也不直接表示人物的 Emotion
或 Appraisal。

-   **positive**：观察视图内至少有一处明确证据。
-   **negative**：观察范围和输入质量足以判断该
    Cue，且没有符合定义的证据。
-   **uncertain**：有相关观察信息，但证据含糊、相互冲突或边界难以稳定判断。
-   **unobservable**：观察条件本身不足以判断该
    Cue，例如无有效语音、画面没有可辨认的人脸、关键区域被遮挡或相对声学基线无法建立。
-   **unlabeled**：Teacher
    尚未成功给出该标签、输出解析失败或调用失败。它是数据流水线状态，不是
    Cue 的语义类别。

训练规则：

  Teacher 状态    是否进入主 BCE 监督  处理方式
  -------------- --------------------- ---------------------------
  positive                是           (y=1, m=1)
  negative                是           (y=0, m=1)
  uncertain               否           (m=0)
  unobservable            否           (m=0)
  unlabeled               否           (m=0)，重试或记录失败原因

不得把"Teacher 没有输出某个 Cue"自动当作 negative。

### 2.2 样本级聚合规则

所有标签都是**样本级存在性/可观察性判断**，不要求输出精确时间戳，但内部可保留证据片段供人工审计。

- **事件型 Cue**（如笑声、哭泣、可见泪水）：在模型实际观察到的任一有效位置发现清晰证据即可为 `positive`。
- **局部状态/韵律 Cue**（如相对语速、相对音高、语调）：完整输入范围内只要有一个可比较片段满足冻结定义，即可为 `positive`；相反 Cue 可以同时为 `positive`，但必须由不同片段或不同语句支持。
- **文本结构 Cue**：只依据本样本实际送入Teacher的中文与英文独立字段，保留语言边界与证据来源，不从音频或视频补推。
- **negative**：只有在相关模态输入完整、相关区域/语音足够可观察、处理过程没有明显截断或覆盖不足时，才表示“观察充分但未发现 Cue”。
- **uncertain**：证据可见但存在真实歧义、强弱处于边界，或采样结果无法支持稳定二分判断。
- **unobservable**：输入损坏/缺失、相关区域或语音不可见/不可听、相对 Cue 缺少可比较基线，或模型实际观察覆盖不足以判断。
- **平台处理边界**：完整视频文件交由API默认处理；无法知道内部帧时间点时不编造逐帧覆盖，也不单凭平台内部过程未知就强制判不可观测。按实际可见性、清晰度和歧义判断四状态。

第一版只训练样本级输出。`support_segments`、原始时间戳、帧索引或分块索引可以作为 Teacher 审计元数据，但不是 Student 的强制监督目标，也不是强制的图节点。

### 2.3 样本级主体约定

第一版采用"样本内任意主体"的语义：

-   视觉 Cue：任意可辨认人物出现符合定义的表现即可。
-   音频 Cue：任意可听到的声音或说话者出现符合定义的声学表现即可。
-   不要求将视觉人物与音频说话者匹配。
-   不把样本级 Cue 解释为特定目标人物的心理状态。
-   对相对音高、相对语速等标签，仍然不能跨说话者直接比较绝对数值；必要的同一说话者参照不足时应标为
    unobservable。

当前采用样本级规则，但尚未对全量完成单人/多人镜头比例审计，不以“基本单人镜头”作为已验证前提。但样本级
Cue
仍不等于严格的人物身份绑定，也不能直接解释为某个指定人物的心理状态。若未来需要主体级情绪解释，应另行升级本体/数据结构。

### 2.4 正例、反例与不可判定状态：必须统一理解

**正例/Positive 不是"人物情绪积极"，反例/Negative
也不是"人物情绪消极"。** 它们只描述某一个指定 Cue
是否在当前模态的规定观察范围中出现。

-   `positive`：该 Cue 存在明确、可复核的证据，对应训练目标 `y=1`。
-   `negative`：观察充分，但没有符合定义的 Cue 证据，对应训练目标
    `y=0`。
-   `uncertain`：观察到相关现象，但是否满足 Cue 定义仍有歧义。
-   `unobservable`：输入或观察条件不足，无法可靠判断该 Cue。
-   `unlabeled`：标注流程未成功产出标签，例如模型调用失败、JSON
    解析失败或 Cue 遗漏；它不是语义标签。

同一条样本可以对不同 Cue 同时具有不同状态。例如，"I am not happy"
可以同时让
`TXT_AFFECT_WORD_POSITIVE=positive`、`TXT_NEGATION_PRESENT=positive`；这并不矛盾，因为两个
Cue 判断的对象不同。

**禁止的简化规则：** 1. 不得把模型未输出的 Cue 自动填为 negative。 2.
不得把 `uncertain`、`unobservable` 或 `unlabeled` 转成 `y=0`。 3.
不得因为样本整体情绪看起来积极/消极，就推断相应的词语、声学或视觉 Cue
必然存在。 4. 不得把一个 Cue 的存在自动推导成另一个 Cue 的存在。

#### 3.2.0 当前停顿规则与原始标签使用口径

当前Audio Teacher只听完整音频，不接收外部VAD区间、F0、响度、语速代理值或ASR转录。代码没有在本轮执行silero-vad/F0统计流水线；不能把模型证据中的听感描述当作已计算的声学数值。

当前Prompt包含的候选规则为：内部停顿≥0.3秒、长停顿≥1.0秒；频繁停顿为连续10秒范围中至少3个合格内部间隔，且须有至少5秒有效语音。首尾静音、缺失音频、padding或分块边界不算停顿。阈值只是已固定在Prompt中的候选定义，尚未经人工金标准验证；本轮实际提交单个完整音频，不做分块聚合。

**资格偏差诊断。** 00:40历史快照中，短于5秒的频繁停顿二分项有2,600条；全量结束后为11,395条（negative 11,381条、positive 14条）。总时长不足5秒不可能包含至少5秒有效语音，这些模型判断与Prompt资格规则存在冲突；冲突清单只用于记录和后续语义审计，不作为当前标签修改或屏蔽条件。

按用户最新要求，长停顿与频繁停顿均和其他Cue一样直接使用大模型原始state及evidence_note：positive→y=1/mask=1，negative→y=0/mask=1，uncertain/unobservable→y空/mask=0。取消此前方案中按时长资格另外屏蔽二分项的计划；该额外屏蔽此前也未实际应用。11,395条诊断项保留原始二分监督，不新增专用门控、覆盖标记或人工确认要求。冻结Prompt不改、不重新调用API；这不表示上述规则冲突已通过人工语义验证。

如后续引入silero-vad测量，则另行固定VAD版本、阈值、有效语音资格和停顿统计，并作为独立诊断/Student特征消融验证；不得宣称本轮Teacher已经使用了这些数值。

#### 3.2.1 相对声学Cue：当前听觉比较与后续数值对照

六个相对Cue为语速快/慢、音高高/低、强度高/低。当前Prompt要求同一样本、同一可比较声音内至少两个足够的语音片段，且信号质量允许比较；不要求三个固定2秒窗口，两个任意相邻词也不自动形成参照。先判断参照成立，再判断是否存在不能由语音内容、句型、增益/距离等解释的明显偏离：无参照为unobservable，有参照无偏离为negative，边界不清为uncertain。

当前由模型听感执行这一流程，未独立测得F0/RMS/语速baseline，也未自动证明“same speaker”或有效语音资格。高mask比例须在人工审计中解释，不能为了增加正例将unobservable改为negative。

后续HuBERT与声学特征对照可采用冻结的VAD单位、有效F0、响度/能量、语速代理量及稳健median/MAD基线；特征与阈值须在源域开发集验证。它们属于后续研究，不是本轮API输入或已执行的冻结数值标准。若缺少可学的正负例或可靠参照，依据独立审计考虑core_deferred，不因维持42维而强行激活。

#### 4.2.1 300 条金标准：分组字段与抽样脚本

**第一步先核验并冻结 `video_source_id`（尚未完成）。**

当前全量清单只有样本ID、双语文本及音视频路径，没有经核实的原视频来源组。`samplenew3_*`命名不能直接当作同源/异源证明；下面是后续抽样算法示意，不是已执行的审计清单或分组脚本。

优先级：

1. 若 MER-Caption+ metadata 已有稳定的原视频/来源字段，直接使用；
2. 若没有，则依据文件命名规则、原始路径或上游数据 ID 构造 `video_source_id`，并随机人工检查至少 50 组；
3. 如果无法可靠构造来源组，就不能声称“按原视频分组无泄漏”，应明确记录限制。

正式抽样规则：每个来源组优先贡献 1 条；若独立来源组少于 300，再从仍有剩余样本的组中按轮次补充。

```python
def sample_audit_set(
    dataset,
    n=300,
    seed=42,
    group_col="video_source_id",
):
    # 返回 sampled_dataset, audit_manifest

    rng = np.random.default_rng(seed)

    groups = {
        group_id: list(indices)
        for group_id, indices
        in dataset.groupby(group_col, sort=True).groups.items()
    }

    for group_id in groups:
        rng.shuffle(groups[group_id])

    selected = []
    round_id = 0

    while len(selected) < n:
        available_groups = [
            gid for gid, ids in groups.items()
            if len(ids) > round_id
        ]
        if not available_groups:
            break

        rng.shuffle(available_groups)

        for gid in available_groups:
            if len(selected) >= n:
                break
            selected.append({
                "group_id": gid,
                "index": groups[gid][round_id],
                "selection_round": round_id,
            })

        round_id += 1

    if len(selected) < n:
        raise ValueError(
            f"Only {len(selected)} samples available for requested n={n}"
        )

    sampled_indices = [x["index"] for x in selected[:n]]
    audit_manifest = {
        "seed": seed,
        "group_col": group_col,
        "n": n,
        "selected": selected[:n],
    }

    return dataset.loc[sampled_indices].copy(), audit_manifest
```

**固定参数**

- 主抽样种子：`42`
- 目标样本数：`300`
- 分组字段：冻结后的 `video_source_id`
- 输出：`audit_manifest.json`
- 300 条及其同源组内其他片段不得进入 Student train/validation。

#### 4.2.2 双标规模：固定 60 条

结合当前中等预算，主方案固定：

- 300 条金标准中 **60 条（20%）** 由第二名标注者独立双标；
- 这 60 条也按 `video_source_id` 分组随机抽取；
- 双标抽样种子固定为 `43`；

- 90 条不再作为默认主方案；若预算增加，可作为额外扩展审计。

-   随机集用于估计自然分布下的 Teacher 质量。
-   定向补充集用于稀有 Cue 诊断。
-   两者分开报告；不能直接把定向补充集与随机集混合后计算自然分布的总体指标。

### 4.4 必须报告的指标

逐模态、逐 Cue 报告：

-   Precision、Recall、F1。
-   正例数、负例数、uncertain 数、unobservable 数。
-   Teacher 预测为正的数量及 Teacher--Human 混淆矩阵。
-   人工双标一致性。
-   置信区间，尤其是稀有标签的区间。
-   每个 Cue 的覆盖率与可观察性比例。

不要只报告 42 个 Cue 的平均 F1。某些 Cue
可能整体准确率很高，但几乎没有正例，或者 Teacher 对其判断经常不可观察。

## 5. 数据划分与泄漏控制

### 5.1 分组优先于随机样本划分

按原始视频、原始来源或能够识别的片段组进行分组划分。尽可能检查：

-   同一原视频切出的近重复片段是否跨 train/validation/test。
-   同一内容是否存在不同文件名、不同编码或不同剪辑。
-   MER-Caption+ 与九个目标数据集是否存在原视频或近重复片段重叠。

只检查样本ID不足以排除泄漏。当前尚未完成可信来源分组、近重复检查或正式train/validation划分；不得写成“已完成分组无泄漏”。

全量先生成伪标签不等于所有伪标签都可用于训练。后续确定300条审计集及来源组后，即使其Teacher标签已经存在，也须在训练角色清单中排除审计样本及同源组；不必为此删除原始API响应。任何定向稀有Cue复核集与最终审计集须分开登记。

### 5.2 推荐数据角色与独立评估

-   `teacher_pilot`：未来必要时单独登记30–50条开发校准；旧30条标签已删除，不作为当前可复现实验结果，也不用于最终性能声明。
-   `gold_audit`：300
    条随机样本，三模态均有人工参考标签；不进入伪标签训练、Student
    训练或早停。
-   `pseudo_train`：排除 `gold_audit` 及其同源视频/来源组之后的训练分组
    Teacher 伪标签。
-   `pseudo_validation`：按原视频/来源分组独立划出，用于 Student
    早停、架构和池化方法的开发比较。
-   `gold_oof_evaluation`：在 Prompt 与模型选择已经冻结后，用于 Teacher
    审计、阈值交叉拟合和 Student 的 out-of-fold 金标准评估。

**300 条金标准的用途约束** 1. Teacher Prompt 与API模型配置 在查看 300
条审计结果前冻结，因此 Teacher--Human 指标可在这 300 条上直接报告。 2.
Student 架构、池化方式、声学特征开关、训练轮数等开发选择优先使用
`pseudo_validation`，不根据 300 条金标准上的结果反复选择模型。 3.
若需要用人工金标准校准每类阈值，使用 5
折分组交叉拟合：每一折的阈值只由其他 4 折决定，并只在该折评估。报告的是
out-of-fold 指标，不是用全 300 条选阈值后再在同一 300 条上计算的结果。
4.
最终部署阈值可以在开发/报告完成后利用全部源域金标准重新拟合，但必须与此前的
out-of-fold
性能报告区分；不能将部署阈值下同一批数据的重算结果称为独立测试性能。 5.
如果某个 Cue
的任一折缺少足够正例/负例，则报告支持数不足和不确定性，不强行给出稳定阈值或性能结论。

### 5.3 九个目标数据集的输入兼容性登记（只看元数据，不看标签）

在最终 zero-shot
评测前，建立一张只记录数据接口和输入可用性的表，至少包含：数据集名称、文本字段与语言、音频是否可用及语言、视频/帧是否可用、时长/分辨率格式、缺失模态比例、对应的预处理器版本。

-   这一步只用于确认输入管线是否能运行，不得查看目标 Emotion
    标签、目标性能或任何标签相关统计。
- Text Student 主模型改为 `google-bert/bert-base-multilingual-cased`，可接收中文和英文，但“编码器支持多语言”不等于不同语言上的 Cue 识别自动具有相同性能。
- 源域按固定字段优先级选择原始文本，缺失时使用 `english` 翻译字段；目标域也必须在不查看标签/性能的前提下预先登记实际文本字段、语言、来源和是否翻译。
- 不得在看到目标标签或性能后临时决定是否翻译、换字段或改预处理。若目标域语言与源域不一致，应在 zero-shot 评测前预注册一种策略（原文优先、统一固定版本翻译，或将文本模态标记为不兼容/不可用）；所有策略都要独立报告，不能静默适配。
-   任何目标域标签都不得用于 Prompt、Teacher、Student、阈值、Cue 选择或
    AMG 检索策略的调整。

## 6. 三个 Student 的训练设计

### 6.1 Text Student：多语言 BERT

```text
chinese、english（独立字段，保留语言边界）
    -> google-bert/bert-base-multilingual-cased
    -> token/分块表征
    -> 各语言池化及可追踪的双语聚合
    -> 15 维独立 sigmoid 分类头
```

- 主模型固定为 `google-bert/bert-base-multilingual-cased`（经典多语言 BERT，中文和英文均可输入）；`FacebookAI/xlm-roberta-base` 可作为后续对照，不是主方案必需组件。
- Teacher与Student读取同一份中文和英文独立字段，分别编码并显式聚合；不把翻译当作额外的独立事件证据。
- 每条样本保留 `text_language`、`text_source`、`is_translation` 元数据用于分层误差分析；除非另做消融，不将这些字段直接拼进正文文本。
- 初始最大长度可设为 512 tokens。超长文本使用确定性分块与样本级聚合，不静默截断；分块之间应保留足够重叠以减少 Cue 跨边界遗漏。
- 第一版允许微调编码器，同时保留冻结编码器的轻量基线。输出 15 个相互独立的 Cue 分数，不使用跨 Cue softmax。

### 6.2 Audio Student：HuBERT + 全时长覆盖 + 声学统计对照

```text
完整中文音频
    -> 16 kHz / mono
    -> Chinese HuBERT-Large（完整编码或重叠分块覆盖全时长）
    -> 时间序列表征
    -> 时间/片段级聚合
    -> 17 维独立 sigmoid 分类头
```

- 不再采用固定 8 个 2 秒窗口作为 Student 主输入。
- 如果 HuBERT 一次编码完整音频超出显存/长度限制，使用重叠分块覆盖 `[0, D]`；保存每块起止时间并在聚合时去重。
- 事件型 Cue 可使用注意力池化或 Top-k 片段聚合；语调 Cue 需要保留一定的时间顺序；简单 mean pooling 作为基线而非唯一方案。
- 保留显式声学特征对照：有效 F0、强度/能量、停顿、中文语速代理量等。比较 HuBERT-only 与 HuBERT + acoustic statistics。
- 六个相对声学 Cue 需要显式基线/片段特征的消融检查；不得只用全音频的一个均值特征就假设模型能学到“相对高/低”。
- VAD、F0 提取、语速代理、停顿阈值、分块重叠和归一化方式须在源域 pilot/开发验证后冻结。

### 6.3 Visual Student：CLIP + 全视频时间覆盖 + 样本级聚合

```text
完整视频时间范围
    -> 确定性帧采样（保存每帧时间戳）
    -> CLIP ViT-L/14
    -> 帧 embedding 序列
    -> mean / max / attention / Top-k 等样本级聚合
    -> 10 维独立 sigmoid 分类头
```

- CLIP ViT-L/14 是图像编码器，不会自行建模帧间时间关系；必须显式加入样本级聚合。
- 采样策略要覆盖完整视频起止范围。初始候选可比较 2 FPS 与 4 FPS，但最终 FPS、最大帧数和采样方式必须依据源域开发集上的 Cue 召回/计算成本对照后冻结。
- API不要求暴露内部帧时间点；Student采用覆盖全时长的确定性采样并记录时间戳，不声明与Teacher严格逐帧对齐。
- 对短暂面部 Cue，比较 mean、max、attention 或 Top-k 聚合；主模型选择只依据源域开发验证集，不用 300 条最终金标准反复调参。
- 可对面部/上半身裁剪做独立消融，但裁剪规则、检测器版本和失败处理必须冻结；`VIS_HEAD_LOWERED` 不能只依赖紧脸部裁剪。
- 5 个 Visual Experimental Cue 不进入主 10 维输出。

### 6.4 统一输出

三个 Student 各自输出 sigmoid 分数：

- Text：15 维。
- Audio：17 维。
- Visual：10 维。

仅一个模态失败时，保留其他模态的有效标签，不默认删除整个样本。训练采样、class weight和损失分母只统计该模态/Cue的有效监督，不能把待处理或失败数量计入负例；也不能把完整音视频输入等同于全部42项均可监督。

合并后得到 42 维样本级 Cue 分数。不同 Cue 不是互斥类别，因此不使用跨 Cue softmax。四状态监督映射保持不变：`positive` / `negative` 参与主损失；`uncertain` / `unobservable` / `unlabeled` 通过 mask 排除。

## 7. 损失函数、噪声处理与阈值

### 7.1 主损失

先使用 masked BCEWithLogitsLoss。对样本 (i)、Cue (k)，只有
positive/negative 参与监督：

$$
\mathcal{L}=\frac{\sum_{i,k}m_{ik}\,\operatorname{BCEWithLogits}(z_{ik},y_{ik})}{\max(1,\sum_{i,k}m_{ik})}.
$$

-   positive：(y=1,m=1)。
-   negative：(y=0,m=1)。
-   uncertain / unobservable / unlabeled：(m=0)。

实现中应明确归一化口径；主基线按有效标签数归一化。若某个 batch
没有任何有效标签，则跳过该 batch 的损失更新。

### 7.2 类别不平衡与伪标签噪声

按以下顺序实验：

1.  普通 masked BCE，作为主基线。
2.  基于训练集有效标签统计的 class-weighted BCE。
3.  如确有必要，再比较 focal loss。
4.  根据 Teacher--Human 审计结果，进行 Cue
    级标签过滤或可靠性加权的消融。

不要直接把 Teacher 自报 confidence
当作真实概率，也不要在没有人工审计的情况下任意设置"低置信度标签一律丢弃"的规则。过滤策略应在源域开发阶段确定并版本化。

### 7.3 阈值选择

-   每类独立阈值，不强制所有 Cue 共用 0.5。
-   源域 validation 用于训练过程和基础模型选择。
-   若使用人工金标准进行阈值校准，应使用 5
    折分组交叉拟合或独立开发/测试划分；每个样本的评估阈值不能由该样本自身标签选择。
-   对正例过少的
    Cue，不应声称其阈值已可靠校准；保留连续分数，并将该类标记为证据不足或暂缓。
-   九个目标数据集不得参与阈值选择。

## 8. Student 评估与进入 AMG 的门槛

### 8.1 Student 指标

逐模态、逐 Cue 报告：

-   Precision、Recall、F1。
-   PR-AUC。
-   support（正/负例数量）。
-   置信区间。
-   不同标签状态的覆盖率。
-   Teacher--Human、Student--Human 结果对照。

整体 macro-F1、micro-F1 只作为补充，不能替代逐 Cue 结果。

### 8.2 Cue 状态决策

每个 Cue 根据以下证据决定是否进入 AMG 主路径：

-   操作性定义是否清晰。
-   人工双标是否足够一致。
-   Teacher 与人工是否一致。
-   随机集是否有足够正负例。
-   unobservable 比例是否过高。
-   Student 在人工参考上的表现是否稳定。
-   与其他 Cue 是否高度重复。
-   在当前固定输入视图下是否真的可观察。

当前流泪训练监督层已恢复902条大模型原始positive。部分相对声学Cue较高的mask比例仍需核验，不是已确定的core_deferred结论。停顿统一保留原始模型标签；资格冲突仅作为后续审计信息，不额外改变当前训练监督。

不提前承诺某个固定F1门槛。若某个 Cue 数据不足、不可观察性过高或
Student 无法稳定学习，应设为 `core_deferred`，而不是为了维持 42
维输出强行保留。

### 8.3 冻结内容

进入 AMG 前冻结：

-   Cue 本体版本。
-   Teacher 模型与版本。
-   各模态 prompt 版本。
-   预处理、采样、有效窗口掩码版本。
-   Student 模型权重与代码 commit。
-   每类阈值版本。
-   人工金标准版本。
-   每个 Cue 的 active/deferred 状态。

## 9. 后续 AMG 图构建的接口约定

建议区分三个概念：

1.  **CueType**：全局本体中的 Cue 类型，例如 `AUD_LAUGHTER_PRESENT`。
2.  **CueAssertion / CueInstance**：某个样本对该 Cue
    的预测结果，包括分数、阈值化状态、模型版本和观察协议。
3.  **局部证据位置**：第一版可选属性，不要求作为独立图节点。

源域 Memory 与目标 Query 应尽量使用相同
Student、相同预处理、相同阈值和相同 Cue 语义。

-   训练集上的源域样本优先使用 out-of-fold Student
    预测建库，避免模型对自身训练样本的预测过于乐观。
-   Teacher 标签用于监督、人工审计与上界对照，不作为默认 Memory 表示。
-   图中可同时保留 Cue
    分数与阈值化结果，不要只存二值标签，以便后续研究软权重检索。
-   目标数据集不参与 Memory 构建策略、阈值或模型的选择。

## 11. 全量运行、失败处理与恢复

### 11.1 调度与限流

当前32个请求并发、360 RPM、1,600,000 TPM；每5秒读取 `runs/mercaptionplus/runtime_config.json`，可原子更新workers/rpm/tpm。执行器允许workers 1–64、RPM 12–1000、TPM不超过1,600,000；范围是代码边界，不代表所有取值均有平台配额或提速保证。减少并发时让多余线程完成在途请求；更新RPM时保留已有429降速，不通过读配置反复清除退避。

同一进程共用全局限速器和持久SQLite队列，不能再按GPU启动两个各自满速的进程。模型推理在平台侧完成，本机主要承担CPU音视频转换、内存、磁盘和网络。当前没有本地Teacher权重/显存推理；双GPU留给后续训练，不决定API并发。

### 11.2 失败分类与实际快照

| 类型 | 当前个数 | 当前处理与后续处置 |
|---|---:|---|
| 完整视频Base64超过当前10,000,000字节预算 | 59 | 完整H.264转码后仍超预算则失败；不裁时长、不缩放、不抽帧。本限制是当前上传实现的验收预算，不宣称是所有视频接口的通用上限。后续若改为托管完整文件URL等方式，须先验证并登记输入/请求协议。 |
| 平台 `data_inspection_failed` | 15 | 保存原始400响应/Request ID并保持未标注；不通过更换内容、改写输入或其他方式规避平台检查。依据平台允许的申诉/复核流程处理，或如实报告缺失。 |
| 平台 `invalid_parameter_error` | 2 | 当前为完整视频URL/数据格式被拒绝，单独检查编码、请求载荷和平台兼容性；不冒充“无Cue”。修复后显式安排补标。 |

### 11.3 重试与停止条件

- 网络、408/429、服务端5xx、输出截断/JSON或schema不完整等，每轮最多3次请求，指数退避并加抖动；首轮处理完再对可恢复失败补跑一轮，单模态累计最多6次。
- 429遵守Retry-After；无则60秒冷却，全局RPM减半。一般“Allocated quota exceeded”按速率限制处理，不仅因出现quota字样就判断余额耗尽。
- 401/402/403或明确余额/欠费错误会全局停止；连续36个任务失败或磁盘余量不足5GiB也停止。未开始/中断任务保留pending，不虚构标签。
- 视频发生平台引擎兼容错误或当前文件预算问题时，可作完整H.264 CRF18转码；仍不合格进入失败清单，不改变模态隔离和完整范围。
- 原子写JSON后才记成功；重启回收running为pending，已有且通过schema的成功记录复用。独占锁防止同目录重复进程。网络超时后平台可能已处理，重试仍存在重复计费可能，不能承诺API端exactly-once。
