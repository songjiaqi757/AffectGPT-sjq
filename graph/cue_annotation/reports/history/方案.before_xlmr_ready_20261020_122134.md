## 2. Cue 语义与状态规范

### 2.1 样本级语义

每个 Cue 表示：

> 在该样本实际可观察的范围内，是否存在可复核证据支持这个 Cue。

它不表示完整原始视频在所有时刻都不存在该 Cue，也不直接表示人物的 Emotion
或 Appraisal。

-   **positive**：观察视图内至少有一处明确证据。
-   **negative**：观察范围和输入质量足以判断该
    Cue，且没有符合定义的证据。
-   **uncertain**：有相关观察信息，但证据含糊、相互冲突或边界难以稳定判断。
-   **unobservable**：观察条件本身不足以判断该
    Cue，例如无有效语音、画面没有可辨认的人脸、关键区域被遮挡或相对声学基线无法建立。
-   **unlabeled**：Teacher
    尚未成功给出该标签、输出解析失败或调用失败。它是数据流水线状态，不是
    Cue 的语义类别。

训练规则：

  Teacher 状态    是否进入主 BCE 监督  处理方式
  -------------- --------------------- ---------------------------
  positive                是           (y=1, m=1)
  negative                是           (y=0, m=1)
  uncertain               否           (m=0)
  unobservable            否           (m=0)
  unlabeled               否           (m=0)，重试或记录失败原因

不得把"Teacher 没有输出某个 Cue"自动当作 negative。

**标签使用补充：不是只使用positive。** 对同一个Cue，positive是“存在”，negative是“观察充分但不存在”；两者共同训练独立二分类，不能理解为积极/消极情绪。uncertain、unobservable保留状态用于审计和覆盖分析，unlabeled保留失败原因；三者当前都不进入主BCE，不当negative、不设成0.5。主模型不因此自动具备四状态预测能力，详见第7节。

### 2.2 样本级聚合规则

所有标签都是**样本级存在性/可观察性判断**，不要求输出精确时间戳，但内部可保留证据片段供人工审计。

- **事件型 Cue**（如笑声、哭泣、可见泪水）：在模型实际观察到的任一有效位置发现清晰证据即可为 `positive`。
- **局部状态/韵律 Cue**（如相对语速、相对音高、语调）：完整输入范围内只要有一个可比较片段满足冻结定义，即可为 `positive`；相反 Cue 可以同时为 `positive`，但必须由不同片段或不同语句支持。
- **文本结构 Cue**：只依据本样本实际送入Teacher的中文与英文独立字段，保留语言边界与证据来源，不从音频或视频补推。
- **negative**：只有在相关模态输入完整、相关区域/语音足够可观察、处理过程没有明显截断或覆盖不足时，才表示“观察充分但未发现 Cue”。
- **uncertain**：证据可见但存在真实歧义、强弱处于边界，或采样结果无法支持稳定二分判断。
- **unobservable**：输入损坏/缺失、相关区域或语音不可见/不可听、相对 Cue 缺少可比较基线，或模型实际观察覆盖不足以判断。
- **平台处理边界**：完整视频文件交由API默认处理；无法知道内部帧时间点时不编造逐帧覆盖，也不单凭平台内部过程未知就强制判不可观测。按实际可见性、清晰度和歧义判断四状态。

第一版只训练样本级输出。`support_segments`、原始时间戳、帧索引或分块索引可以作为 Teacher 审计元数据，但不是 Student 的强制监督目标，也不是强制的图节点。

### 2.3 样本级主体约定

第一版采用"样本内任意主体"的语义：

-   视觉 Cue：任意可辨认人物出现符合定义的表现即可。
-   音频 Cue：任意可听到的声音或说话者出现符合定义的声学表现即可。
-   不要求将视觉人物与音频说话者匹配。
-   不把样本级 Cue 解释为特定目标人物的心理状态。
-   对相对音高、相对语速等标签，仍然不能跨说话者直接比较绝对数值；必要的同一说话者参照不足时应标为
    unobservable。

当前采用样本级规则，但尚未对全量完成单人/多人镜头比例审计，不以“基本单人镜头”作为已验证前提。但样本级
Cue
仍不等于严格的人物身份绑定，也不能直接解释为某个指定人物的心理状态。若未来需要主体级情绪解释，应另行升级本体/数据结构。

### 2.4 正例、反例与不可判定状态：必须统一理解

**正例/Positive 不是"人物情绪积极"，反例/Negative
也不是"人物情绪消极"。** 它们只描述某一个指定 Cue
是否在当前模态的规定观察范围中出现。

-   `positive`：该 Cue 存在明确、可复核的证据，对应训练目标 `y=1`。
-   `negative`：观察充分，但没有符合定义的 Cue 证据，对应训练目标
    `y=0`。
-   `uncertain`：观察到相关现象，但是否满足 Cue 定义仍有歧义。
-   `unobservable`：输入或观察条件不足，无法可靠判断该 Cue。
-   `unlabeled`：标注流程未成功产出标签，例如模型调用失败、JSON
    解析失败或 Cue 遗漏；它不是语义标签。

  `TXT_AFFECT_WORD_POSITIVE`                                                       

  Text:                        "I am not happy."                    positive       词面 Cue 仍存在；否定由
  `TXT_AFFECT_WORD_POSITIVE`                                                       `TXT_NEGATION_PRESENT`
                                                                                   单独记录

  Audio:                       清楚听到笑声                         positive       声学事件出现
  `AUD_LAUGHTER_PRESENT`

同一条样本可以对不同 Cue 同时具有不同状态。例如，"I am not happy"
可以同时让
`TXT_AFFECT_WORD_POSITIVE=positive`、`TXT_NEGATION_PRESENT=positive`；这并不矛盾，因为两个
Cue 判断的对象不同。

**禁止的简化规则：** 1. 不得把模型未输出的 Cue 自动填为 negative。 2.
不得把 `uncertain`、`unobservable` 或 `unlabeled` 转成 `y=0`。 3.
不得因为样本整体情绪看起来积极/消极，就推断相应的词语、声学或视觉 Cue
必然存在。 4. 不得把一个 Cue 的存在自动推导成另一个 Cue 的存在。

#### 3.2.0 当前停顿规则与原始标签使用口径

当前Audio Teacher只听完整音频，不接收外部VAD区间、F0、响度、语速代理值或ASR转录。代码没有在本轮执行silero-vad/F0统计流水线；不能把模型证据中的听感描述当作已计算的声学数值。

当前Prompt包含的候选规则为：内部停顿≥0.3秒、长停顿≥1.0秒；频繁停顿为连续10秒范围中至少3个合格内部间隔，且须有至少5秒有效语音。首尾静音、缺失音频、padding或分块边界不算停顿。阈值只是已固定在Prompt中的候选定义，尚未经人工金标准验证；本轮实际提交单个完整音频，不做分块聚合。

**资格偏差诊断。** 00:40历史快照中，短于5秒的频繁停顿二分项有2,600条；全量结束后为11,395条（negative 11,381条、positive 14条）。总时长不足5秒不可能包含至少5秒有效语音，这些模型判断与Prompt资格规则存在冲突；冲突清单只用于记录和后续语义审计，不作为当前标签修改或屏蔽条件。

按用户最新要求，长停顿与频繁停顿均和其他Cue一样直接使用大模型原始state及evidence_note：positive→y=1/mask=1，negative→y=0/mask=1，uncertain/unobservable→y空/mask=0。取消此前方案中按时长资格另外屏蔽二分项的计划；该额外屏蔽此前也未实际应用。11,395条诊断项保留原始二分监督，不新增专用门控、覆盖标记或人工确认要求。冻结Prompt不改、不重新调用API；这不表示上述规则冲突已通过人工语义验证。

如后续引入silero-vad测量，则另行固定VAD版本、阈值、有效语音资格和停顿统计，并作为独立诊断/Student特征消融验证；不得宣称本轮Teacher已经使用了这些数值。

#### 3.2.1 相对声学Cue：当前听觉比较与后续数值对照

六个相对Cue为语速快/慢、音高高/低、强度高/低。当前Prompt要求同一样本、同一可比较声音内至少两个足够的语音片段，且信号质量允许比较；不要求三个固定2秒窗口，两个任意相邻词也不自动形成参照。先判断参照成立，再判断是否存在不能由语音内容、句型、增益/距离等解释的明显偏离：无参照为unobservable，有参照无偏离为negative，边界不清为uncertain。

当前由模型听感执行这一流程，未独立测得F0/RMS/语速baseline，也未自动证明“same speaker”或有效语音资格。高mask比例须在人工审计中解释，不能为了增加正例将unobservable改为negative。

后续HuBERT与声学特征对照可采用冻结的VAD单位、有效F0、响度/能量、语速代理量及稳健median/MAD基线；特征与阈值须在源域开发集验证。它们属于后续研究，不是本轮API输入或已执行的冻结数值标准。若缺少可学的正负例或可靠参照，依据独立审计考虑core_deferred，不因维持42维而强行激活。

3. 如果无法可靠构造来源组，就不能声称“按原视频分组无泄漏”，应明确记录限制。

正式主审计抽样规则：每个来源组优先贡献1条；若独立来源组少于300，再从仍有剩余样本的组中按轮次补充。该规则的评估总体为“来源组均衡审计”，不自动代表31,327条样本的自然分布；保留组大小、选中轮次和抽样算法，不用未经计算的权重声称自然分布无偏。

若研究目标要求样本自然分布指标，应在查看审计答案前另外固定样本概率抽样，或严格计算纳入概率并加权；不同设计分别报告。下列代码仍只是组均衡算法示意。原始来源无法核实时，可登记已验证重复簇与来源未知状态，但不能将重复簇冒充video_source_id；具体训练退路见第5.1节。

```python
def sample_audit_set(
    dataset,
    n=300,
    seed=42,
    group_col="video_source_id",
):
    # 返回 sampled_dataset, audit_manifest

    rng = np.random.default_rng(seed)

    groups = {
        group_id: list(indices)
        for group_id, indices
        in dataset.groupby(group_col, sort=True).groups.items()
    }

    for group_id in groups:
        rng.shuffle(groups[group_id])

    selected = []
    round_id = 0

    while len(selected) < n:
        available_groups = [
            gid for gid, ids in groups.items()
            if len(ids) > round_id
        ]
        if not available_groups:
            break

        rng.shuffle(available_groups)

        for gid in available_groups:
            if len(selected) >= n:
                break
            selected.append({
                "group_id": gid,
                "index": groups[gid][round_id],
                "selection_round": round_id,
            })

        round_id += 1

    if len(selected) < n:
        raise ValueError(
            f"Only {len(selected)} samples available for requested n={n}"
        )

    sampled_indices = [x["index"] for x in selected[:n]]
    audit_manifest = {
        "seed": seed,
        "group_col": group_col,
        "n": n,
        "selected": selected[:n],
    }

    return dataset.loc[sampled_indices].copy(), audit_manifest
```

**固定参数**

- 主抽样种子：`42`
- 目标样本数：`300`
- 分组字段：冻结后的 `video_source_id`
- 输出：`audit_manifest.json`
- 300 条及其同源组内其他片段不得进入 Student train/validation。

#### 4.2.2 双标规模：固定 60 条

结合当前中等预算，主方案固定：

- 300 条金标准中 **60 条（20%）** 由第二名标注者独立双标；
- 这 60 条也按 `video_source_id` 分组随机抽取；
- 双标抽样种子固定为 `43`；
- 三个模态使用同一批 60 条样本，便于统一计算 human–human agreement；
- 90 条不再作为默认主方案；若预算增加，可作为额外扩展审计。


### 4.3 稀有 Cue 补充

对笑声、哭泣、可见泪水等稀有 Cue，若随机 300
条中的正例或负例不足，可定向补充约 50--200 条，或补充到足以分析为止。

- 主审计集按第4.2.1节来源组均衡抽样，报告该总体下的Teacher质量；自然样本分布指标需要独立登记相应抽样/加权设计。
- 定向补充集用于稀有Cue诊断；同时覆盖Teacher阳性、阴性及边界样本，不只复核阳性。若定向结果用于改训练策略，应登记独立开发角色，不能混作最终gold。
- 对拟作为独立最终诊断的数据，先预留候选来源组并排除出训练/早停，再定向抽样。已参与训练的同源样本不能事后变成独立测试。
- 两者分开报告；不能直接混合后计算自然分布总体指标。按现有伪标签比例，均匀抽300个样本约只有1.9个频繁停顿伪阳性，此为预算估计，不是人工真阳性数；不足以保证逐类五折阈值稳定。

### 4.4 必须报告的指标

逐模态、逐 Cue 报告：

-   Precision、Recall、F1。
-   正例数、负例数、uncertain 数、unobservable 数。
-   Teacher 预测为正的数量及 Teacher--Human 混淆矩阵。
-   人工双标一致性。
-   置信区间，尤其是稀有标签的区间。
-   每个 Cue 的覆盖率与可观察性比例。

不要只报告 42 个 Cue 的平均 F1。某些 Cue
可能整体准确率很高，但几乎没有正例，或者 Teacher 对其判断经常不可观察。

## 5. 数据划分与泄漏控制

### 5.1 分组优先于随机样本划分

按原始视频、原始来源或能够识别的片段组进行分组划分。尽可能检查：

-   同一原视频切出的近重复片段是否跨 train/validation/test。
-   同一内容是否存在不同文件名、不同编码或不同剪辑。
-   MER-Caption+ 与九个目标数据集是否存在原视频或近重复片段重叠。

只检查样本ID不足以排除泄漏。当前尚未完成可信来源分组、近重复检查或正式train/validation划分；不得写成“已完成分组无泄漏”。

**来源不可恢复时的可执行退路（尚未执行）：** 已检查的samples.json及源CSV没有可信原视频来源字段。先查询可用来源元数据，再做服务器内可复现的文件哈希、音视频内容近重复候选检索及人工抽查，冻结重复簇、规则、阈值与来源可信度。最终group_id使用可信来源或已验证重复簇；未关联文件可作为单文件簇但source_status=unknown，不能以不同文件名宣称原视频独立。排除审计/诊断已知同源或重复簇后可开展明确注明分组限制的工程基线，无须无限等待无法恢复的身份；正式zero-shot报告仍披露残余泄漏风险。重复检索仅看内容/元数据，不用目标标签/性能调节阈值。

角色清单先抽取并隔离gold_audit/独立诊断候选组，剩余组以约90/10划分pseudo_train/pseudo_validation（种子44；组级多标签支持平衡，不拆组凑比例）。三模态使用同一角色，某模态缺失不改变其他模态角色。冻结成员后统计每类各角色有效正负数及覆盖率；某类验证支持不足则如实登记，不反复换种子挑有利结果。角色冻结前不开始正式epoch训练。

全量先生成伪标签不等于所有伪标签都可用于训练。后续确定300条审计集及来源组后，即使其Teacher标签已经存在，也须在训练角色清单中排除审计样本及同源组；不必为此删除原始API响应。任何定向稀有Cue复核集与最终审计集须分开登记。

-   `teacher_pilot`：未来必要时单独登记30–50条开发校准；旧30条标签已删除，不作为当前可复现实验结果，也不用于最终性能声明。
-   `gold_audit`：300
    条随机样本，三模态均有人工参考标签；不进入伪标签训练、Student
    训练或早停。
-   `pseudo_train`：排除 `gold_audit` 及其同源视频/来源组之后的训练分组
    Teacher 伪标签。
-   `pseudo_validation`：按原视频/来源分组独立划出，用于 Student
    早停、架构和池化方法的开发比较。
-   `gold_oof_evaluation`：上述gold_audit在Prompt/Student模型选择冻结后的评估视图，采用分组阈值交叉拟合；不是额外可混入训练的300条，也不是源域Memory的Student折模型训练。后者需另行训练，见第9节。

**300 条金标准的用途约束** 1. Teacher Prompt 与API模型配置 在查看 300
条审计结果前冻结，因此 Teacher--Human 指标可在这 300 条上直接报告。 2.
Student 架构、池化方式、声学特征开关、训练轮数等开发选择优先使用
`pseudo_validation`，不根据 300 条金标准上的结果反复选择模型。 3.
若需要用人工金标准校准每类阈值，使用 5
折分组交叉拟合：每一折的阈值只由其他 4 折决定，并只在该折评估。报告的是
out-of-fold 指标，不是用全 300 条选阈值后再在同一 300 条上计算的结果。
4.
最终部署阈值可以在开发/报告完成后利用全部源域金标准重新拟合，但必须与此前的
out-of-fold
性能报告区分；不能将部署阈值下同一批数据的重算结果称为独立测试性能。 5.
如果某个 Cue
的任一折缺少足够正例/负例，则报告支持数不足和不确定性，不强行给出稳定阈值或性能结论。

## 6. Cue 提取器（三个 Student）的训练设计

本节是待实现的训练规格，不代表模型已训练。三个提取器分别学习 Text 15、Audio 17、Visual 10 个独立 Cue；文本编码器指定为XLM-RoBERTa Base，音视频编码器复用现有Chinese HuBERT-Large、CLIP ViT-L/14权重。文本模型当前下载未完成，完整权重/tokenizer及加载验收是训练前置检查。各模态独立优化和选择 checkpoint，共用数据角色清单，输出按本体固定顺序合并为 42 维。首版不采用多模态融合来预测单模态 Cue，避免从其他模态猜测当前模态证据。

### 6.1 独立实现入口与数据契约

建议新增项目根目录 `cue_student/`，包含发布验收、角色划分、Dataset/collate、三路模型、训练、评估与推理模块；这些模块当前尚未实现。原 `AffectGPT/train.py` 及 MERCaptionPlus Dataset 读取 openset/reason/english，优化 LLM token 生成损失，不能仅修改旧 YAML 就视为 Cue 提取器训练。无需为三路 Cue 训练加载 Qwen 或原 Q-former/LoRA 融合链路。

训练输入契约：

- 从 `runs/mercaptionplus/samples.json` 读取双语文本与原始 `audio_path/video_path`。已清理的 `media/audio`、`media/video` 及历史 `submitted_*_path` 不作为当前 Dataset 路径。
- 从 `labels.csv` 读取监督，按发布版本 `ontology.json.cue_ids[modality]` 数组顺序构造 `targets[B,K]` 与 `label_mask[B,K]`；不得依赖 CSV 行序或 Cue 字符串排序。K 分别为 15/17/10。
- `label_mask` 只控制损失与相应伪标签指标，不能作为分类输入；Teacher state、evidence_note、openset、reason、目标 Emotion/description 同样不能进入预测特征。
- `language_present`、`modality_present` 与真实采样/帧长度生成的 `time_mask` 分别描述实际输入，不能与 Teacher 的 `label_mask` 混用。一种模态失败不删除其他模态。
- 媒体按固定版本在服务器内存中转换；如缓存冻结编码器特征，key 包含源文件、编码器权重、tokenizer/空间预处理/时间采样哈希及位置。缓存只在服务器，冻结模型必须 eval、无随机增强；编码器解冻后不复用旧特征作为可微训练输入。
- 各模态样本如果没有任何有效标签，可以从该模态训练迭代中排除并登记原因，但仍保留在主角色清单与完整输出统计中。

### 6.2 Text：共享 XLM-R 双语编码与融合

```text
chinese -> 共享 XLM-R -> token mask 池化 -> h_ZH
english -> 共享 XLM-R -> token mask 池化 -> h_EN
[h_ZH * a_ZH; h_EN * a_EN; a_ZH; a_EN]
    -> 小型融合 MLP / dropout -> 15 logits
```

- 主编码器为 `FacebookAI/xlm-roberta-base`，服务器预定目录为 `AffectGPT/models/xlm-roberta-base/`。已有config对应hidden_size=768；审查时下载状态仍为downloading，tokenizer尚不能离线加载，不能将目录存在视为可训练。下载完成后校验revision、权重与tokenizer文件哈希并做离线加载/forward/backward验收。两个字段分别编码，保留语言边界；每条样本只计算一次15维损失，不将译文作为第二个独立训练样本。
- `a_ZH/a_EN` 来自字段是否真实存在，缺失字段置零表征并屏蔽。全量中文非空，英文缺失 588 条，不能把空串编码后的特殊 token 当正常英语参与等权平均。两字段都缺失时标记文本输入不可用。
- 首版采用共享XLM-R编码器、带token mask的mean pooling和上述拼接MLP；首个特殊token（`<s>`）池化或语言门控作为后续独立对照。输入使用该模型自己的tokenizer及特殊token规则，不沿用BERT专属分词、段ID或特殊token假设。词面Cue可以从任一语言取证，语义判断不能靠所有Cue通用的双语max规则替代；共享分类器学习融合。
- 长度须用XLM-R自己的tokenizer对全量中英文重新统计（含特殊token）；当前分词器文件未齐，统计待完成。原109/101 tokens属于旧编码器统计，不适用于XLM-R，不能据此宣称128可覆盖源域。暂以`max_length=512`和动态padding作为待验证起点，并按实际tokenizer/config允许长度核验；完成统计后可在源域开发比较128/256/512并冻结。遇到overflow必须检测：使用确定性分块回退，初始重叠32 tokens，记录语言/块位置，在语言内聚合后再融合，不静默截断。
- 第一轮主模型微调 XLM-R 与融合头；保留冻结 XLM-R 的轻量基线。多语言编码器支持某语言，不构成该语言 Cue 性能已经验证的证据。
- `text_language/text_source/is_translation` 用于登记和分层误差分析；现有 samples.json 未完整提供这些 provenance，可靠信息补登记，未知值填 unknown，不编造原始语种。单语/固定翻译推理协议见第5.3节。

### 6.3 Audio：完整 HuBERT 时序表征与样本级分类

```text
原始完整音频 -> mono / 16 kHz -> HuBERT 有效帧序列 [T,1024]
    -> 带 time_mask 的聚合器 -> 17 logits
可选声学对照：归一化前波形 -> F0/能量/VAD/内部停顿等序列及有效性标记
```

- 输入元数据共 31,327 条：median=2.761 秒、p99=10.105 秒、max=26.912 秒，超过20秒仅5条。两张 A800 80GB 在审查时空闲；首版优先完整音频编码，是否可微调及实际 batch 容量必须通过显存 smoke test 确认。
- 不复用原固定8个2秒窗口和短音频补到2秒的主输入逻辑。保留真实时长，按总采样点/时长分桶组 batch，动态右侧 padding；模型 attention mask 与卷积下采样后的有效帧 mask 均须正确处理，padding 不参与池化。
- 首个轻量基线：冻结 HuBERT、eval 模式，从最后一层有效时间表征做 mean pooling + MLP。再比较逐 Cue temporal attention/Top-k；语调的顺序候选使用带位置的轻量时序模块。候选只按 pseudo-validation 比较，不把简单 mean 的结果当作编码器能力上限。
- 需要分块时才启用完整时间轴回退；起止、重叠及有效帧归属写入配置/manifest。重叠位置只计一次，块边界和补零不得计成停顿。完整编码与分块编码是两个预处理版本，不能静默混用。
- 现有 feature extractor `do_normalize=true`。遵循预训练输入处理，同时从归一化前波形计算声学对照；各块独立归一化可能削弱块间音量变化。比较 HuBERT-only 与 HuBERT + acoustic features，而非假定单个全局均值已保留相对声学信息。
- 六个相对 Cue 的统计须包含局部量、可靠参照、有效性标记；多说话者条件不能直接以全样本 F0/语速均值当作同一说话者基线。VAD/F0失败标记为特征缺失，不能自动将现有 Cue 标签改 negative 或改变 label_mask。
- 停顿在原始连续时间轴上计算，排除首尾静音、padding及重叠重复。声学统计归一化参数仅拟合 pseudo_train；VAD/F0/停顿规则在源域开发后冻结。长停顿、频繁停顿继续普通标签监督，不增加时长资格门控。

### 6.4 Visual：全时段采样、空间覆盖与聚合

```text
原始视频（只解码视频流）
    -> 确定性2 FPS采样，保存实际PTS、首帧与最后可解码帧
    -> 逐帧 CLIP ViT-L/14 [T,768]
    -> 带 time_mask 的样本级聚合 -> 10 logits
```

- 首版以2 FPS为起点；4 FPS是唯一首轮时间密度对照。视频 max=26.92秒、p99约10.095秒，按实际帧数编码；采样索引去重，读取真实PTS，帧采样覆盖完整时段不等于逐帧观察或保证捕获所有短暂事件。
- 分批编码全部所选帧后再聚合，不为固定长度只截取前若干帧；动态 padding 的重复/虚拟帧不能参加聚合。对更长的未来输入，采用显式分段完整覆盖回退，记录协议，不静默降低FPS。
- 当前 CLIP processor 默认224中心裁剪，会丢弃宽屏两侧。空间主候选采用保比例缩放补边保留全画面，继续使用预训练的颜色与数值归一化；与默认中心裁剪进行源域对照后冻结选择，不假定补边必然更优。
- 首个轻量基线冻结 CLIP、eval、mean pooling + MLP；再比较逐 Cue attention/Top-k。必要时另做面部/上半身多区域消融，冻结检测器、区域合并及失败回退。任意主体语义不能变成只保留中央人物；VIS_HEAD_LOWERED需保留躯干参照。
- 对眼部/流泪等细粒度 Cue，记录缩放后的实际可辨认性；不能把高分辨率Teacher伪标签视为224图像上必然可学。流泪仍使用普通原始监督，不附专用阳性门控。
- 不读取音轨或额外字幕文本作为视觉特征。画面烧录字幕尚未遮挡，Student同样可能利用文字捷径；将字幕遮挡/区域对照作为源域审计与消融，规则变更版本化，不宣称现有视觉Teacher已物理隔绝字幕。5个Visual Experimental Cue不进入主10维输出。

### 6.5 样本级弱监督与统一输出

每个 Cue 的标签描述整条样本内的存在性，不是每个时刻的状态。**先聚合，再计算一次样本级损失**。对一条阳性视频/音频，不给每帧/每块复制阳性标签；目前没有可信的帧级、块级或人物级强监督。Teacher证据文本与近似时间戳只用于审计，不直接转成强定位真值。

训练模型返回 logits；损失使用 BCEWithLogits；推理再 sigmoid 得到各 Cue 分数。15/17/10个输出相互独立，不做跨Cue softmax，也不将相反Cue强制互斥：不同片段可分别支持高/低、快/慢。

推理保留每类连续分数、版本与输入有效性，按第7.3节使用冻结阈值。无输入时输出不可用标记及空分数，不能用全零冒充明确不存在。Teacher label_mask在推理时不可获得，也不允许作为输入；“mask=0位置没训练损失”不代表模型已学会输出uncertain/unobservable。第一版不是四状态识别器，详见第7.4节。

### 6.6 分阶段优化与首轮参数起点

以下是**待验证的起始配置**，并非已调优结果；先做第6.7节检查，再依据pseudo-validation冻结真实配置。每个提取器先单GPU训练，两个GPU可分配不同模态，互相隔离输出目录。

| 阶段 | 可训练参数 | 初始学习率 | 轮数上限 / 早停 |
|---|---|---|---|
| Text主模型 | XLM-R + 融合/分类头 | encoder 2e-5；新头 1e-4 | 10个完整epoch；patience=3 |
| Audio/Visual轻量基线 | 冻结encoder，仅聚合器/分类头 | 新模块 1e-3 | 20个完整epoch；patience=4 |
| Audio/Visual后续微调 | 从选定基线初始化，解冻末2个Transformer块及末端归一化，其余冻结 | encoder 1e-5；新模块 1e-4 | 10个完整epoch；patience=3 |

- 优化器首版 AdamW；weight_decay=0.01，bias/归一化参数不衰减；warmup占总optimizer steps的10%，随后线性衰减；dropout=0.1，gradient_clip_norm=1.0。完整optimizer参数写入配置。
- 先以有效batch=32条样本为起点，microbatch由最短/最长样本显存检查决定；音频/视觉可按采样点/帧数预算分桶并梯度累积，记录实际样本数、有效标签数及optimizer steps。OOM时先减microbatch，不静默裁时长或丢帧。
- 预处理及损失保持float32稳定性；设备支持时使用bf16 autocast，实际精度写入日志。随机种子42做首轮，配置冻结后以43/44复跑最终候选，报告均值/离散程度，不挑最有利seed。
- 逐epoch完整遍历训练角色中的该模态有效训练样本，明确采样器和drop_last；不照搬原60 epochs × 5000 iters。普通BCE先跑通，再单独比较第7.2节加权损失；每次只改变已登记因素。
- 每个epoch评估一次同一pseudo-validation。固定其可评估Cue集合（至少各有一个有效正、负例），以macro AP为早停主指标、masked BCE为同分辅助；集合为空时以masked BCE为预登记回退。报告每类支持数，不能把极少正例的AP当稳定结论。
- 保存best与last checkpoint，含模型、optimizer、scheduler、scaler（如使用）、RNG、global step、角色及发布哈希。单次长时训练须可恢复；日志/特征/权重全部只写服务器。
- 音视频解冻和更复杂聚合均为后续实验；若相同划分下没有稳定提升，保留轻量模型并如实报告，不以参数量代替Cue提取证据。最终重训若纳入pseudo-validation，须固定先前选定训练长度并重新计算训练统计，此后不得再将该集称为独立验证。

### 6.7 正式训练前的最小实现验收

1. 数据发布验收：成员、任务键、42维本体顺序、标签映射、数据角色无交叉、源路径可用；每类train/validation有效正负支持可复核。
2. 三路各自完成小批次forward/backward：输出维度正确、loss/梯度有限；覆盖负例、缺失英文、全部label_mask=0、部分模态失败、最短/最长输入和变长padding。
3. 比较同一样本单独输入与不同padding长度batch输入的eval结果，在预登记数值容差内一致；验证padding不参加池化，时间采样不遗漏尾部，分块回退不重复累计。
4. 在仅来自pseudo_train的小子集上确认能够降低损失，并检查每类预测分布，排除所有Cue恒正/恒负。该检查不作为泛化性能报告。
5. 单GPU先完成一个可恢复的短训练/验证闭环，核对best选择与断点恢复；工程通过后才能启动全量epoch训练。不得把现有23项标注流水线测试算成提取器测试。

## 7. 标签使用、损失函数、噪声处理与阈值

### 7.1 positive 与 negative 共同监督

**不是只训练positive。** 对每一个Cue，positive表示证据存在，negative表示观察充分且未发现该Cue。两个状态共同建立分类边界；只保留positive会缺少“何时不应报出这个Cue”的约束。Negative不是消极情绪标签，positive也不是积极情绪标签。

| 原始状态 | 含义 | 主分类目标y | label_mask | 当前处理 |
|---|---|---:|---:|---|
| positive | 存在明确Cue证据 | 1 | 1 | 阳性监督 |
| negative | 观察充分但无该Cue | 0 | 1 | 阴性监督 |
| uncertain | 有信息但判断含糊/冲突 | 空 | 0 | 保留状态与证据，不参与主BCE |
| unobservable | 观察条件/比较基线不足 | 空 | 0 | 保留不可观察原因，不当阴性 |
| unlabeled | 标注调用/解析未成功 | 空 | 0 | 保留流水线失败，不当语义标签 |

例如VIS_SMILE_PRESENT：有明确微笑用y=1；面部清楚且没有微笑用y=0；嘴部不可辨认用mask=0。对TXT_AFFECT_WORD_NEGATIVE，“sad”出现仍是该Cue的positive，而非negative。标签和情绪极性必须分开。

主损失使用逐元素masked BCEWithLogits，以有效标签数归一化：

$$
\mathcal{L}=\frac{\sum_{i,k}m_{ik}\,\operatorname{BCEWithLogits}(z_{ik},y_{ik})}{\max(1,\sum_{i,k}m_{ik})}.
$$

实现先把无效y替换成有限占位值（如0），再以mask取有效损失；禁止将空值转NaN后算BCE再乘0，也禁止把占位0当真实阴性。一个样本仅屏蔽部分Cue时，其余Cue继续训练。单GPU有效batch全部mask=0时不更新optimizer/scheduler并登记计数。

梯度累积按整个有效batch的有效标签总数归一化，不能无条件平均不同有效标签数microbatch的mean loss；需预先统计分母或累积未归一化梯度后正确缩放。后续DDP采用全局有效标签分母并补偿梯度平均；某rank局部全mask时仍参加同步，只有全局无监督才统一跳步，防止死锁或不同rank进度不一致。

### 7.2 类别不平衡与Teacher噪声

按顺序比较：普通masked BCE主基线 -> train-only加权BCE -> 必要时focal。首版使用完整有效负例，不为了只保留阳性而删除负例；不同时叠加强过采样、大阳性权重和focal。

加权对照初始规则：每类仅在pseudo_train的mask=1位置统计N+、N-；当两者均非零时令 `pos_weight=min(20,max(1,sqrt(N-/N+)))`，使用相同有效标签数分母。规则及统计保存到checkpoint，不从validation/gold/目标域拟合权重；这是待比较配置，不是已证明最优公式。加权后的sigmoid分数不直接当校准概率。

- N+=0：登记无阳性支持，该类检测/阈值不可可靠学习，暂不承诺active；不得产生无穷权重或用别的Cue伪造阳性。
- N-=0：同样登记缺乏阴性辨别证据。全mask类不进入损失；保留固定输出槽位和不可用说明。
- 当前全量阳性：频繁停顿197、笑声378、哭泣387、相对高音高411、自身原因归因458、成功结果508、流泪902。划分后须重新统计，不能用全量计数替代train-only统计。
- 音频全量mask=0比例29.59%；相对高音高67.00%、频繁停顿56.22%。这些是不确定/不可观察/失败的覆盖信息，不是可随意添加的negative，也不直接决定删除Cue。
- Teacher自报confidence不能当真实概率；不把uncertain设为y=0.5，不根据证据文本长度猜置信度，不因用户要求保留原始停顿/流泪而附加专用阳性门控。
- 可靠性加权/噪声过滤若需人工证据，使用独立开发审计；第4节最终gold不用于反复选择训练权重和架构。若用其开发，必须变更角色并建立新的独立评估，不能重复宣称测试独立。

### 7.3 阈值选择及训练/推理的区别

训练保留所有有效positive和negative；推理对全部Cue输出连续分数。AMG若只选择超过阈值的Cue作为存在性断言，那只是推理/建图选择，不代表训练只使用positive。未超过阈值不能自动解释为人工确认的“不存在”，输入不可用也不能解释为negative。

- 每类独立阈值，首轮以0.5作为明确标注“未校准”的工程参考，不宣称最优。
- 只用源域pseudo-validation选择的阈值标为“Teacher一致性阈值”，与人工校准阈值区分。
- 人工校准使用第5节独立开发/测试或5折分组交叉拟合，选择规则预先固定（首版最大化开发折F1，同分取较高阈值）；样本自己的人工标签不能影响评估自己的阈值。
- 某折没有足够正负支持时，保留未校准阈值和连续分数并报告证据不足，不借用该评估折答案补阈值，不强行给稳定性能结论。
- 人工交叉拟合后可用全部源域gold拟合部署阈值，但该部署阈值下重算同批gold不是独立测试性能。校准涉及最终Student权重、输入协议与损失版本，切换模型不能默认沿用。
- 九个目标数据集不参与阈值、Cue激活、checkpoint或预处理选择。

### 7.4 四状态标签保留，不默认改成四分类

第一版学习的是在有效可判定监督下的Cue存在性，固定42个二分类输出；uncertain/unobservable保留用于覆盖率、审计与误差分层，unlabeled用于失败登记。二分类低分不是unobservable，接近0.5也不是经过训练的uncertain；没有监督的区域可能产生高分，须通过独立人工参考验证覆盖偏差。

如后续确需模型自动判断可观察性，可单独预注册辅助任务：positive/negative对应“Teacher判可判断”，unobservable对应“Teacher判不可观察”；uncertain和unlabeled不强行并入任一类。其标签描述Teacher观察判断而非人类真值，必须单独验证；不把辅助头默认作为删除当前监督、替代人工审计或屏蔽推理阳性的门控。当前主方案不增加此辅助头，也不把四状态压成一个跨Cue softmax。

## 8. Student 评估与进入 AMG 的门槛

### 8.1 伪标签一致性与人工准确性分别报告

逐模态、逐Cue报告Precision、Recall、F1、PR-AUC（首版固定采用Average Precision/AP实现）、有效正负support、uncertain/unobservable/unlabeled覆盖率及置信区间。macro/micro只作补充，无正例/无负例等不可评估类逐项列出，不能默默补零或按模型更换平均类集合。区间按已知来源组聚类bootstrap；无可信分组时明确相关性限制。

- Student–Teacher：在pseudo-validation按该集label_mask计算，只衡量拟合Teacher；无人工审计时这是工程指标，不能称人类准确率。
- Teacher–Human：盲审后报告四状态覆盖、Teacher可判定子集的混淆矩阵，同时登记Teacher在人工可判定样本上的uncertain/unobservable/失败，不能只报选择性准确率而隐藏拒判。
- Student–Human：以人工参考的可判定状态决定评估范围，不用Teacher mask二次过滤；单独报告输入缺失和无法输出的比例。
- 按语言字段缺失、时长、多人/遮挡/小脸、原始状态及稀有Cue分层分析，分层定义在源域冻结；不得把target性能反馈回训练。

300条主审计保持第4节登记的抽样总体。当前均衡来源组抽样不自动等于样本自然分布；稀有Cue定向集单独报告，其阴性/边界样本也必须覆盖，不能只复核Teacher阳性。

### 8.2 Cue激活证据

依据定义清晰度、人工双标一致性、Teacher–Human差异、独立正负支持、可观察覆盖率、Student–Human稳定性及重复性决定active/deferred。高总体accuracy可能来自大量negative，不能单独证明提取器有用。人工审计可以用于按预登记证据决定是否部署该Cue，但不能据此反复改架构后继续称同批gold为独立测试。

流泪902条原始positive、长停顿3181条、频繁停顿197条均继续普通监督，不附额外门控。高mask比例不是已经确定deferred的结论；缺少正负支持或人类表现不足时，可保留42维槽位但将该类设为core_deferred，不为凑42个active强行作存在性声明。

### 8.3 进入AMG前冻结

冻结本体/Cue顺序、Teacher/Prompt、数据发布与角色划分哈希、源文件和缓存版本、语言/空间/时间预处理、有效输入mask规则、Student代码与权重、损失/统计/随机种子、阈值来源及版本、人工gold与抽样总体、active/deferred状态。实际结果、失败与已知不可学风险同时发布，不能以文件存在代替验收。

## 9. 后续 AMG 图构建的接口约定

区分CueType（本体类型）、CueAssertion（样本级预测/存在性断言）、局部证据位置（第一版可选审计属性）。第一版无人物绑定、无经过验证的强定位输出。

每个样本的接口保留42维连续scores、本体顺序、每类阈值与active/deferred、modality_present、输入有效性/协议、checkpoint版本；缺失模态对应空分数与不可用标记。Teacher监督mask不传给推理器。图中可按阈值选择positive断言，但同时保存连续分数，未选中、不可用和明确不存在不得混为一类。

### 9.1 OOF建库与阈值交叉拟合是两项任务

- 第5/7节gold的5折主要用于阈值交叉拟合：不要求为每折重新训练一个Student，因为gold本身已排除出Student训练。
- 对Student训练过的源域样本进行OOF预测建Memory，则需额外训练折模型。建议在完成单次三路基线后，按来源组固定5个outer folds；每个样本仅由未用其所属组训练的checkpoint预测。
- 各outer训练部分内部再划分早停/阈值开发角色；不能用outer留出折选epoch或阈值后仍声称该折是严格独立预测。架构候选预冻结，登记原开发数据使用边界；最终gold始终不参与折模型训练/早停。
- 记录每折权重、成员、早停与阈值来源。OOF特征不能仅标成“最终Student”而隐藏生成模型；需要每模态约5套折训练，另有最终部署模型，费用与工期独立估算。
- OOF折模型与最终全量Student权重不同，Memory/Query虽共享本体、结构及预处理，分数分布仍可能不同；仅用源域开发数据比较尺度/阈值兼容性并登记。不得声称严格相同权重，不用目标标签修正。
- Teacher标签只作监督、审计与对照，不是默认Memory表示。若先用单次模型做原型，明确标注in-sample检索的乐观偏差，不能冒称OOF结果。

### 11.3 重试与停止条件

- 网络、408/429、服务端5xx、输出截断/JSON或schema不完整等，每轮最多3次请求，指数退避并加抖动；首轮处理完再对可恢复失败补跑一轮，单模态累计最多6次。
- 429遵守Retry-After；无则60秒冷却，全局RPM减半。一般“Allocated quota exceeded”按速率限制处理，不仅因出现quota字样就判断余额耗尽。
- 401/402/403或明确余额/欠费错误会全局停止；连续36个任务失败或磁盘余量不足5GiB也停止。未开始/中断任务保留pending，不虚构标签。
- 视频发生平台引擎兼容错误或当前文件预算问题时，可作完整H.264 CRF18转码；仍不合格进入失败清单，不改变模态隔离和完整范围。
- 原子写JSON后才记成功；重启回收running为pending，已有且通过schema的成功记录复用。独占锁防止同目录重复进程。网络超时后平台可能已处理，重试仍存在重复计费可能，不能承诺API端exactly-once。
